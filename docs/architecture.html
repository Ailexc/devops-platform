统一基础设施层

一个 Compose 工程，三个基础组件，多租户隔离

所有业务项目不再自带数据库 / 缓存 / 消息队列，全部收敛到 infra/docker-compose.yml。 通过「一实例多库 / db index / 队列」三种隔离维度，让 7 个系统安全共享同一套基础组件，显著降低资源占用与运维成本。

统一网关层 · Traefik

一个入口，收敛全部域名

统一网关 devops-gateway（Traefik v3.7）聚合 7 个系统到 *.devops.orb.local。 按 Host 规则把请求转发到各系统前端容器，前端 nginx 再同源反代到各自后端（无跨域）。本工程不依赖 OrbStack 特性，可平滑迁移到云端单机部署。

统一管理编排层

一套命令，管理全部系统

根目录 Makefile + scripts/ 提供统一编排，覆盖基础设施、构建、启动、数据重置、备份、网关的全生命周期，并统一处理各项目 compose 文件路径差异。

核心命令

make bootstrap拉起统一基础设施（PG/Redis/RabbitMQ）并创建 10 个业务库
make start [P=xxx]统一启动入口；RESET_ON_START=true 先重置出厂态再启动
make reset [P=xxx]数据重置回出厂态（drop schema → migrate → 幂等种子）
make backup统一备份（SQLite 文件 + PG dump + MySQL dump）
make gateway-up启动统一网关（Traefik，入口 *.devops.orb.local）
make status / logs / portal状态总览 · 单系统日志 · 打开门户

数据可靠性设计

一键重置不搞坏

每个系统重置前先 DROP SCHEMA 清空统一库再重建种子（双保险），全量重置还会重建 openfga / cmdb-go 等 sidecar。

保守迁移

统一化迁移全程保留旧数据容器/卷，确认无误后才清理；每个阶段都有备份兜底。

环境变量可覆盖

门户应用跳转地址支持 APP_URL_* 覆盖，云端部署不改代码。

健康检查

统一基础设施全部配置 healthcheck，bootstrap 等待就绪后才建库，避免竞态。

架构设计要点 · 面试叙事

为什么这样设计

一套架构，标准统一

7 个系统共享统一数据层 + 统一消息中间件 + 统一网关，杜绝"一个小组维护多套架构"——符合企业内实际工程组织方式。

多租户隔离思想

PG 一实例多库、Redis db index、RabbitMQ 队列，用最轻量的方式实现资源隔离，兼顾成本与安全边界。

职责清晰的分层

入口 / 网关 / 应用 / 基础设施 / 编排五层解耦：网关只做路由、前端同源反代、后端无状态可扩容、基础设施独立演进。

统一消息中间件

RabbitMQ 统一 Celery broker，各系统 Worker 独立可扩容，队列命名规范隔离任务来源——微服务化异步架构的标准形态。

数据可靠性优先

一键重置双保险、保守迁移、统一备份、RESET_ON_START——把"演示数据可靠性"作为第一原则。

本地 ↔ 云端平滑

统一网关纯 Traefik 实现，本地 OrbStack 用 *.orb.local，云端 DNS 泛解析即可复用，为 ECS 部署预留通道。
