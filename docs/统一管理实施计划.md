# DevOps 平台合集 —— 统一管理整体方案与实施计划

> 版本：v1.0（2026-08-16）· 状态：待评审
> 背景：7 个系统独立并行开发，底层资源（数据库/缓存/重置方式/端口）未统一，难以统一构建、统一部署、统一重置。目标是把它们收敛成"一套平台、一套命令、一个入口"，支撑面试在线 Demo 与个人作品集。

---

## 一、背景与目标

### 1.1 现状痛点（为什么必须统一）

| 痛点 | 现状 |
|------|------|
| **数据库三套混用** | SQLite（Authentication / ReleaseManager / WorkFlowCenter 轻量模式）、MySQL（CloudManager）、PostgreSQL（EventManager / PermissionCenter / TaskManager） |
| **重置方式五花八门** | `reset.sh`、`reset_db.sh`、`make seed-reset`、`manage.py reset_data`、`manage.py reset_demo`、`scripts/reset-all.sh`……各写各的 |
| **端口冲突** | TaskManager 占 `5432/6379`、EventManager 占 `5433/6380`、PermissionCenter 占 `15432/16379/18081/19080`、CloudManager 占 `3306`——同时起必撞 |
| **无统一入口** | 各系统独立 `*.orb.local` 域名，无统一网关/统一门户串联 |
| **文档与实现不一致** | 例：WorkFlowCenter README 写 PG16+Redis，实际 compose 是 SQLite 轻量模式 |
| **编排各自为政** | 有的用 nginx 反代、有的内置 Traefik、有的宿主机预编译镜像、有的依赖 docker.sock/kind |

### 1.2 目标

1. **统一数据库**：全部 PostgreSQL，一实例多库（`devops_<项目>`），统一 `DATABASE_URL`
2. **统一缓存**：一个 Redis（本地按 db index 隔离），统一 `REDIS_URL`
3. **统一入口**：Traefik 统一网关（域名/路径路由 + 自动 HTTPS）
4. **统一命令**：顶层 `Makefile` —— `make bootstrap/build/up/down/seed/reset/status/deploy`
5. **统一重置**：每个项目一个标准 `reset` 入口，顶层一键全量重置（"快照还原"语义）
6. **面试可用**：一键拉起 → 门户进 → 逐个演示；平时停机省钱；面试后一键下线

## 二、现状盘点（已核实）

| 项目 | 后端 | 前端 | 数据库 | 缓存/队列 | 现状重置 | 统一改造点 |
|------|------|------|--------|-----------|----------|------------|
| **Authentication** | FastAPI | React19 | SQLite | —（内置 Traefik forwardAuth） | `reset.sh` | SQLite→PG；门户并入统一网关；保留 SSO/JWKS |
| **CloudManager** | Django | Vue3 | **MySQL** | Redis | `reset_db.sh` | **MySQL→PG**（settings + init.sql + 方言差异）；去 nginx 并入网关 |
| **EventManager** | Django+Go | React | PG16 | Redis+RabbitMQ | `make init-all` | 已有 PG；接统一 PG/Redis；去端口映射 |
| **PermissionCenter** | Go | Vue3 | PG16 + OpenFGA | Redis | `make seed-reset` | 已有 PG；接统一 PG/Redis/OpenFGA；**镜像需在 x86_64 重编** |
| **ReleaseManager** | Django | React18 | SQLite | —（executor 依赖 **docker.sock + kind/kubeconfig**） | `scripts/reset-all.sh` | SQLite→PG；**kind 演示在 ECS 需降级为 Docker 部署模拟** |
| **TaskManager** | Django+Celery | Vue3 | PG15 | Redis+Celery | `manage.py reset_data` | 已有 PG；接统一 PG/Redis；去端口冲突 |
| **WorkFlowCenter** | Django5 | Vue3 | **SQLite（轻量模式）** | — | `manage.py reset_demo` | SQLite→PG（README 目标态即 PG16）；补 Redis/Celery 可选 |

> 关键事实：
> - **唯一同时提供"门户入口"的是 Authentication 的 Portal（React19 应用广场）**——它就是全家桶的统一门户。
> - 4 个系统已是 PG（改连接即可），3 个是 SQLite/MySQL（需迁移）。
> - Celery 仅 TaskManager 在用；RabbitMQ 仅 EventManager 声明（CloudManager 计划中，实际未跑）。

## 三、目标架构（单机 Docker Compose，本地 / 阿里云 ECS 通用）

```
                      用户 / 面试官
                           │
                           ▼
                ┌──────────────────────┐
                │  Traefik 统一网关       │  ← 统一入口 + 自动 HTTPS
                │  :8080 → 各系统域名路由  │
                └──────┬───────────────┘
        ┌──────────────┼──────────────────────────┐
        ▼              ▼              ▼            ▼
  [统一门户]     [7 个业务系统]   [统一 PostgreSQL]   [统一 Redis]
  Authentication  各项目 backend/     postgres:16       redis:7
  Portal(React19)  +frontend(静态)   一实例 7 库         按 db index 隔离
                                     devops_*         (0~6)
        │              │
        └──────────────┴──────────► 顶层 Makefile：bootstrap/build/up/seed/reset/deploy
```

- **本地**：OrbStack 自动域名（`*.devops.local` 风格）；**ECS**：`http://公网IP:8080`（或备案后域名 443）
- **每个项目 = 一个 compose 服务组**，最终收敛为一个根级 `docker-compose.yml`（或 `docker-compose.override` 分层）

### 统一规范（4 条军规）

1. **统一环境变量**：`DATABASE_URL` / `REDIS_URL` / `SECRET_KEY` / `RENDER`(可选)，各项目从 `.env` 或统一 `env` 组读取
2. **统一启动入口** `start.sh`：`migrate → 幂等 seed → 启动`；支持 `RESET_ON_START=1`（先全量重置再种）——本地与 ECS 同一条命令
3. **统一重置入口** `make reset [P=项目]`：`drop schema → migrate → seed`，即"回到出厂态"
4. **幂等种子**：以版本标记/空表判断，重复部署不重复插入

## 四、分阶段实施计划

### Phase 0 —— 顶层脚手架（先立规矩，不动业务代码）

| 项 | 说明 |
|----|------|
| 产出 | 根目录 `Makefile`、`scripts/`、`.env.example`、`db/init.sql`、`docs/` 命令手册 |
| 内容 | `make bootstrap`（起 pg+redis 容器+建 7 库）、`make build`、`make up/down`、`make seed`、`make reset [P=]`、`make status` |
| 验收 | 一条 `make bootstrap && make status` 能看到统一基础设施就绪 |
| 工作量 | 小（半天~1 天） |

### Phase 1 —— 数据库统一 PostgreSQL（本地先行）

| 子项 | 项目 | 说明 |
|------|------|------|
| 改连接 | Event / Permission / Task | `DATABASE_URL` 指向统一 PG 的各自库，去端口映射 |
| SQLite→PG | Auth / Release / WorkFlow | Django 类较顺（migrations 重生成 + JSONField/布尔差异）；Release 的 executor 只改读取 |
| **MySQL→PG** | CloudManager | `DB_ENGINE`→postgres、`init.sql`→PG 方言、布尔/自增/JSON 字段兼容——**最大改造点** |
| 验收 | 每项目 `make up P=<项目>` 连统一 PG 跑通；`make seed` 幂等 |

### Phase 2 —— 统一启动入口 + 重置语义

- 每项目补 `start.sh`（migrate + 幂等 seed + 启动），支持 `RESET_ON_START=1`
- 统一 `make reset` 全量/单项目（收编 reset.sh/reset_db/seed-reset/reset_data/reset_demo 为一套命名）
- 验收：`make reset && make up` 后所有系统回到演示初始态

### Phase 3 —— 单机 Compose 编排（Traefik 网关 + 统一基础设施）

- 根级 `docker-compose.yml`：`traefik + postgres + redis + (7 应用组)`
- Traefik 域名/路径路由到各系统前端；Portal 作为入口
- **本地 OrbStack 全量验证**（先本地跑通，再上云）
- 验收：`make up` 后 `http://<host>:8080` 进门户 → 逐个系统可点

### Phase 4 —— 部署到阿里云 ECS（面试在线 Demo）

- ECS（2核4G，Ubuntu）装 Docker Compose，`git clone + make up`
- 访问 `http://112.124.69.224:8080`；展示页 CTA 指向该地址
- **节省停机策略**：平时 `docker compose stop`/实例停机，面试前开机（额度 300 元内随意用）
- 验收：外网打开门户 → 各系统可用；`make reset` 演示中途还原

### Phase 5 ——（可选）域名与收尾

- `.CN` 域名：需**包年包月**实例才能 ICP 备案（当前按量付费 ECS 不支持，见计费调研）；不急可先用 IP
- 面试后一键下线：`make down` + 释放实例/删仓库

## 五、风险与前置依赖

| 风险 | 说明 | 对策 |
|------|------|------|
| **ReleaseManager 的 kind/K8s 演示** | executor 挂 `/var/run/docker.sock` + kubeconfig，ECS 上无 kind 集群 | 降级为「Docker 部署模拟发布」或仅本地演示；不阻塞整体 |
| **CloudManager MySQL→PG** | 方言/字段差异 + 种子脚本要重写 | 单独子任务，最后做；不阻塞其他系统先上线 |
| **PermissionCenter 镜像** | golang 镜像源不可用、需宿主机预编译；ECS 是 x86_64（本地 Mac 是 arm64） | 在 ECS 上重编 `GOOS=linux GOARCH=amd64`，或预置构建机 |
| **内存预算** | 2核4G 跑全家桶偏紧（估 2.7-3G） | 加 2G swap；非重点系统可先只起 2-3 个演示；卡再临时变配 |
| **Celery worker** | TaskManager 需 worker；单机同容器起 | `start.sh` 里同容器起 gunicorn + celery worker（或演示用 EAGER） |
| **端口** | 统一后全部容器内互通，不再暴露到宿主机 | 只用 Traefik 一个入口暴露 `:8080` |

## 六、需要你拍板的决策点

1. **范围**：第一阶段先全量统一，还是**先上 3-4 个重点系统**（如 门户+认证+权限+发布/工作流）跑通线上 Demo，其余按 Phase 1 节奏跟上？
2. **CloudManager MySQL→PG**：投入最大，建议**排在后面**；线上 Demo 可先不包含它，或保留独立演示。同意吗？
3. **ReleaseManager K8s 演示**：线上降级为 Docker 部署模拟，接受吗？
4. **统一门户**：以 Authentication Portal 为准（应用广场 + SSO），其余系统作为"已接入/待接入"卡片，对吗？
