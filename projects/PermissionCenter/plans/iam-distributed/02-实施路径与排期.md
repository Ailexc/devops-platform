## 关键任务分解

### P0 契约（先冻结，后面全靠它）
- 判定请求/响应字段终稿（CheckRequest/FilterRequest/Material/QueryDecl——已定稿于 SDK 设计文档 §1.1/§3.2）
- bundle v2 schema：接口级快照 + 组成员 + **数据范围声明**（resource_scope 四形态）+ **查询声明**（QueryDecl）+ revision/签名
- 门禁规则：必填字段、试算语义（不可算 400 拒+出路 / 不可达 502 重试）、档位降级条件、**集合式名单规模上限**（默认 500，超限建议条件式）
- 审计回传格式（决策日志最小集：who/action/model/id/verdict/reason/ts/trace）

### P2 Agent（工程量最大，拆四步）
1. bundle 客户端（拉取→校验→原子激活→last-known-good——接口级已有，扩 v2 字段）；
2. **数据级求值器**（四形态比对——与中心 `evalAttrCond` 同款语义，注意判定语义一致性测试）；
3. 端点层（/v1/check /v1/filter /v1/manifest /healthz + fail-closed 语义）；
4. 决策回传（异步批量 + 环形缓冲 + best-effort，**绝不阻塞判定**）。

### P3 SDK
- core 一份 + Django 壳（middleware+ORM 信号）+ Gin 壳（middleware+GORM Callback）+ go-restful 壳（Filter）；
- 声明驱动取材器 FetchByDecl（模板拼装，零系统知识）；
- 契约测试套件（6 条 + 全 POST 路由命中）——**壳发布门禁**：三壳必须过同一套件。

### P4 试点（选型理由）
- **Django 试点**：内部主力栈（用户口径：Python 项目全是 Django），验证"最顺路径"；
- **BK-CMDB**：最硬骨头（全 POST、go-restful、三维度、Mongo）——**最硬的通过了，其余都是坦途**；二开同仓所以改 Filter 无协调成本。

## 迁移与并存策略

```
阶段一（P1-P3）：新旧并存——旧两层（网关判定+中心数据级）照跑，新链路只进试点
阶段二（P4）：试点切新链路，对照验证（同一操作新旧判定结果一致）
阶段三（P5）：网关判定下线（只认证）；中心数据级判定降为例外/过渡；存量应用按迁移手册挂 SDK
回滚：网关判定开关保留一个版本周期（配置回切即回旧链路）；Agent/SDK 均可独立摘除（fail-closed 注意：摘除=该系统数据级拒，需连同路由降级）
```

**并存期口径纪律**（防两套口径）：文档同时标注"当前实装"与"目标架构"，以 01 §4 三清单为准；面试边界表（04）是唯一话术出口。

## 验收清单（全局）

1. **契约测试套件**：三壳 × 6 条（无权限拒且未执行/范围外改删零副作用/列表过滤/取材失败拒/停 Agent fail-closed/全 POST 路由命中）全绿；
2. **demo 扩展**：新增"SDK+Agent 本地数据级判定"场景（替代/并列现 demo 场景 19-21 的中心判定路径）——两路结果一致性对照；
3. **试点走通**：Django 试点 + BK-CMDB 接入记录（接入耗时、改动行数、坑）；
4. **门禁反例**：缺查询声明的包拒发、试算失败拒发、超限名单拒发；
5. **审计闭环**：Agent 判定 → 回传 → 中心聚合视图可查（"谁在何时被怎么判"一处查全）；
6. **回归**：旧 demo 22 场景不回退（中心侧存量能力不动）。

## 明确不做（本轮边界）

- **SDK 多语言全量**（Java/Spring 排 P7，看试点反馈）；
- **投影代码删除**（只降级定位，存量兼容保留）；
- **A9 版本锚定+影响面**（既定 P1，不并入本轮）；
- **bundle 事件推送加速撤销**（演进项，先靠轮询+force-remote 兜底）；
- **DB 层强制（行级安全）**（备用重手段，试点被绕过问题真实出现再上）。
