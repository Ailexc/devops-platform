# 01 · 目标架构与方案框架

## 1. 目标架构全景

```
用户请求
  │
  ▼
[网关] 只做认证：JWT 校验 + 注入身份头（X-Auth-*）；不做鉴权判定；保留流量防护（防爆破/TLS）
  │
  ▼
[业务系统]
  ├─ [SDK 中间件]（一次接入全接口）——三步收口
  │    ① 接口级：调本地 Agent（包内存比对，µs）
  │    ② 取材：声明驱动（QueryDecl 拼装查询）走业务原生数据通道拿判定材料
  │    ③ 数据级：调本地 Agent（清单/条件/变量比对，µs）
  │    全过 → 执行业务（此刻才落库）；任一不过 → 拒，零副作用
  ├─ [Agent 旁挂容器]（纯判定器：只算不算数）
  │    轮询拉 bundle（按 app 切分）→ 原子激活 → 本地判定 → 决策日志异步回传
  │    fail-closed / last-known-good
  └─ 业务原生数据通道（自己的 DB/查询语义——数据不出本系统）
  │
  ▼（低 QPS：拉包/回传审计/force-remote 强一致档白名单）
[权限中心] 只管策略生命周期：申请/审批/版本/到期/审计 + 按 app 打包 + 发布门禁 + manifest
            不存资源数据（投影退役为例外）、不在判定热路径上
[身份源 HR/AD] ──SCIM──▶ 权限中心（用户/组织/组副本）——破除老系统"人存 CMDB"的自循环
```

## 2. 组件职责（六件，边界写死）

| 组件 | 干什么 | 不干什么（边界） |
|---|---|---|
| **网关** | 认证（JWT）+ 身份头注入 + 流量防护 | **不鉴权**（接口级也不判）——鉴权全在业务侧 |
| **SDK** | 三步收口中间件 + 声明驱动取材 | 不判定（只是判定的搬运工）、不存规则 |
| **Agent** | 拉包、纯判定（内存/包比对）、决策日志回传 | **不查数据、不发业务外呼、不持有数据凭证** |
| **中心** | 策略生命周期（申请/审批/版本/到期/审计）+ 打包分发 + 发布门禁 | 不在判定热路径、不存资源数据（投影=例外） |
| **发布门禁** | schema 校验 + 试算自检 + 语义档位 | 不做人工把关（机器自动） |
| **审计回传** | Agent 决策日志异步批量回传 → 中心聚合视图 | 不阻塞判定（best-effort + 本地缓冲） |

## 3. 判定链路（四种操作 × 两种判定材料）

| 操作 | 接口级 | 数据级材料 | 数据级判定 |
|---|---|---|---|
| 增 | 动作码匹配（包内） | 请求参数即"未来的行"（可选条件校验） | 包内比对 |
| 查（点/列表） | 同上 | 取材（声明驱动取行/候选行） | 点=谓词对单行；列表=filter 挑行 |
| 改 | 同上 | 旧属性（取材）+ 新值（请求） | 谓词比对，**判过才落库** |
| 删 | 同上 | 旧属性（或仅 ID） | 同上，**判过才删** |

判定材料四形态：**all**（全量）/ **集合式**（ID 清单入包）/ **条件式**（谓词对行属性）/ **变量式**（条件值=请求者身份）。选型三问见接入手册（语义 > 频率 > 性能）。

## 4. 与现状实装的关系（★ 防理想化核心节）

**这次升级不是推翻重来，是"补完 + 重心迁移"。三清单：**

### 保留（已实装，新架构继续用）
- 中心策略生命周期全套：申请/审批/SoD/TTL 回收/审计（A 层 + A8 定制需求卡）
- bundle 按 app 打包 + revision + 签名 + agent 拉取激活（`bundle/` + `iam-agent`，demo 场景 11 已验证接口级本地判定）
- 数据契约 + 发布门禁雏形（A2 试算自检 + 失败二分——新架构的 QueryDecl 门禁**复用同一机制**）
- 三通道同步/巡检/深对账（A4/A5）——**定位变更**：从"判定主路"改为"例外通道与跨源聚合"，不删
- 确认制时钟/降级三档——保留给中心判定的例外场景

### 新增（本计划的工程主体）
- Agent **数据级求值器**（四形态比对——现在 agent 只会接口级）
- Agent 判定端点 `/v1/check`、`/v1/filter`、`/v1/manifest` + **决策日志回传**
- SDK：core + Django/Gin/go-restful 三壳 + 契约测试套件
- 中心：`/v1/manifest` 端点、bundle v2（范围声明入包）、发布门禁补 QueryDecl 校验与试算、审计回传接收与聚合视图
- 网关退场鉴权（forwardAuth 判定 → 只认证），旧两层平移路径

### 退役/降级（定位变更，不是删除）
- **投影**：从"判定主路"降为"跨源聚合例外 + 兼容存量"——新接入（policy-to-data）不建投影
- **中心数据级热判定**（check-instance/filter 主流量）：从"统一模式"降为"例外/过渡通道"——主路移到 Agent 本地判
- **新鲜度三档的主舞台**：投影退场后，主场景的判定材料是业务实时取的行（天然新鲜），新鲜度机制转移给例外通道与 force-remote 档

## 5. 协议清单（全部已定义，见两份既有文档）

| 端点 | 方向 | 用途 | 状态 |
|---|---|---|---|
| `GET /v1/bundles/{app}` | Agent→中心 | 拉策略包（revision/checksum 校验/原子激活——**checksum 防损坏；防篡改签名=演进项**） | 【已实装】接口级部分 |
| `GET /v1/manifest` | SDK/Agent→Agent→中心 | 本应用生效声明（路由映射/QueryDecl/范围） | 【设计定稿】 |
| `POST /v1/check` | SDK→Agent | 点判定（含 attributes/changes） | 【已实装】接口级（现网 `/v1/local/check`，体 `{user,app,action}`——协议形状演进中）；数据级【设计定稿】 |
| `POST /v1/filter` | SDK→Agent | 列表挑行（rows 进 allowed_ids 出） | 【设计定稿】 |
| `POST /v1/decisions` | Agent→中心 | 决策日志异步批量回传 | 【设计定稿】 |
| force-remote 强一致档 | Agent→中心 | 高危动作判定前回源实时判（复用 force-remote 标记 + `/v1/authz/check` 通道） | 【已实装】中心侧；独立 `/v1/force-check` 端点=【设计定稿】（可选收敛） |

## 6. 设计原则回顾（全文纲，面试收束）

1. **判定跟着数据走**：数据在谁家、判定在谁家——可控可装 agent 就 policy-to-data，跨源例外才 data-to-policy；
2. **声明驱动**：取材怎么取、范围是什么，全由能力包声明（数据契约）说了算——**core/Agent 零系统知识**（系统知识承载在壳与声明里，"零 X"类表述一律带此范围限定）；维度条件**下推只是预过滤**（性能优化），行内字段仍过 Agent 二次判——正确性裁决永不外移；
3. **fail-closed**：任何错误=拒，永不放行；判不过零副作用；
4. **发布方责任制**：声明质量是发布方的成本，门禁把关、运行期归因；
5. **控制面中心化、数据面去中心化**：规则真相一处、判定执行到处——K8s 同款格局。
