# 04 · 治理、审计与叙事

## 1. 发布门禁（细化——声明不合格挡在发布期，见接入手册 §4.1 的执行引擎）

| 门 | 执行者 | 语义（失败二分，与数据契约门禁同款） |
|---|---|---|
| ① schema 完整性 | 中心（注册/发布 API） | 查询声明 URL/Method/Payload/fields 缺任一 → 400 拒 + 缺项清单 |
| ② **试算自检** | 中心（发布时真调一次取材） | 不可算（格式/字段对不上）→ 400 拒 + 出路（降接口级）；不可达（发布方接口暂挂）→ 502 可重试，**不计契约拒绝** |
| ③ 语义档位 | 中心 | 声称数据级但无查询声明 → 拒发或**降级为接口级包**；集合式名单 > 上限（默认 500）→ 拒 + 建议条件式 |

试算执行器注意：发布是**控制面操作**，调外部符合既有 Sync 设计（不违反"判定不依赖外部"红线——红线管的是判定热路径）；试算结果留档（谁、何时、试了什么、结果）供归因。

## 2. 审计闭环（分布式后"集中审计"的实现）

```
Agent 判定 → AuditBuffer（本地环形，尽力而为）→ 批量 POST /v1/decisions → 中心聚合视图
```

- **归因三查询**（延续现有 reason 归因字典）：判定日志按 user/app/action/reason 检索；取材失败率按发布方聚合（谁家声明烂一眼可见）；丢弃计数按 agent 聚合（审计管道自身健康）；
- **定期审阅**：owner 复核"谁在用我什么权限"（既有机制）；取材失败率/异常模式进审阅清单。

## 3. 撤销时效三道兜底（传播窗口的正面账）

| 道 | 机制 | 覆盖 |
|---|---|---|
| 1 | bundle 轮询（POLL_INTERVAL，默认 30s） | 常规撤销，窗口 ≈ 轮询周期 |
| 2 | **force-remote 强一致档**（高危写标记，复用既有） | 高危动作判定前回源实时判——撤销立即生效 |
| 3 | **短时效受限令牌**（写方向，既有审批受限令牌） | 写操作凭证寿命封顶 TOCTOU |

话术："常规撤销是传播窗口级（秒~分钟），高危动作有强一致档兜底，写方向还有短时效凭证——三道叠起来，剩下的窗口是明知且可接受的。"

## 5. 面试边界表（说什么 / 不说什么——防超前宣称）

| 说 | 不说 |
|---|---|
| "Agent 数据级求值是设计定稿、P2 实施中" | 不说"已上线" |
| "声明驱动取材 + 发布门禁是我们的规范" | 不说"开源产品都这么做"（它们做不了强制） |
| "撤销有传播窗口，三道兜底" | 不说"即时撤销"（分布式下不存在） |
| "防绕过靠统一 SDK+审计+审阅三层，可要求 DB 层行级安全" | 不说"绝对防绕过"（enforcement 无法完全中心化） |
| "每个部件有行业锚点，我们是按场景组装" | 不说"全新发明" |
| "投影退役为主路径，跨源例外保留" | 不说"投影全删了"（代码还在，定位变了）|
