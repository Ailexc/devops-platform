调用方令牌（JWT 示例）

Payload · 身份 + 授权声明
{ "sub": "client:ops-tool", "aud": "cmdb", "iss": "iam.permission-center", "scope": "cmdb:host:list cmdb:host:read cmdb:host:create", "grant_id": "GR-20260805-001", "data_scope": {"type":"all"}, "exp": 1785916800, "iat": 1785913200 }
Signature · 验签
RS256(base64url(header).base64url(payload), iam_private_key)
授权落地物（权限判断语法）
授权生效 = 动作级 Casbin 规则 + 数据级 OpenFGA 关系。
# 1) Casbin 动作级（PDP / bundle 本地决策） p, client:ops-tool, cmdb, cmdb:host:list, *, allow p, client:ops-tool, cmdb, cmdb:host:read, *, allow p, client:ops-tool, cmdb, cmdb:host:create, *, allow # 2) OpenFGA 数据级（实例过滤） type host relations: define reader: [user, group, client] tuple (host:web-01, reader, client:ops-tool) tuple (host:web-02, reader, client:ops-tool)
决策模式对比（治 v1 的"每请求都重"）
模式延迟一致性适用说明
① 远程每请求高（跨服务 RTT）强管理操作/低 QPSv1 的做法，全量会成瓶颈
② 本地 bundle低（内存判断）最终一致（秒~分钟级）读/普通请求策略快照推到边缘，agent 本地 Casbin
③ 混合（推荐）低读最终一致 + 写强一致全部普通请求本地决策，高风险写操作强制远程
请求模拟器（PEP 解析 + PDP 决策）
选主体 + 请求，观察"请求 → 动作映射 → 决策"。
🔌 双模式接入（Q6）：发布能力的前提 = 至少有一条强制路径（网关 or SDK）。接入网关的应用零改造；无法入网关的应用用 SDK（程序级接入）。
应用注册表（效能部门 3 小组 + 运维部门若干小组）
应用所属接入模式负责人能力可发布能力
Tier 1 · 网关托管
应用接入 IAM 网关（APISIX/Traefik），流量必经网关，鉴权零改造。发布能力时自动注册受保护路由。
# 网关路由自动注册（发布能力时生成） http: routers: cmdb: rule: PathPrefix(`/api/v1`) middlewares: [pep-token, iam-authz] service: cmdb-svc middlewares: iam-authz: forwardAuth: address: http://iam-server:8080/v1/gateway/check authRequestHeaders: [X-User, X-App, X-PEP-Token]
✅ 应用零改造 · 身份由网关注入 · 每请求鉴权（缓存/bundle 优化）
Tier 2 · SDK 程序级接入
无法入网关的应用（如运维部门小应用）安装 IAM SDK，本地验签 JWT + 按需调 PDP。
# 安装（Go 示例，其余语言类似） go get github.com/permission-center/sdk-go # 配置（应用启动时加载） iam: jwks_url: https://iam.permission-center/jwks client_id: ops-tool client_secret: ****** enforce: local-first # local-first | force-remote # 中间件（Gin 一行接入） r.Use(iamsdk.AuthMiddleware())
⚠️ 接入方需改造成本（装依赖+配置）——这是与网关模式的核心取舍
