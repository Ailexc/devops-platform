# 实施清单：同步组件进程隔离与多副本加固（iam-sync 拆分）

> **版本**：v1.1（2026-09-23 对抗审查修订：3 S + 8 M + 5 L 全吸收）｜ **状态**：**可开工**
> **v1.1 关键修订**：① S10 补语义硬断言（原 EXIT=0 探不到循环死活，做错了也能绿）；② reset.sh/周边脚本面纳入 S7（原漏掉主 reset 路径必不启动 iam-sync）；③ healthz 改纯容器内、禁宿主端口（宿主 8090 已被 devops-gateway 占用 + scale 端口冲突）；④ 锁覆盖四执行点 + 逐轮 recover/defer 释放顺序写死；⑤ 消费组三个语义（起点 $/仅成功 ACK/XAUTOCLAIM 位置）定死；⑥ S6 改向（DeleteTuple 错误传播 > 防双写）；⑦ 场景编号 13→19 修正；⑧ 构建双链描述对齐真实 Makefile/Dockerfile（产物 /usr/local/bin 非 /app）
> **触发**：四问拷问（异常连累/性能竞争/可用性/独立观测）暴露三后台 goroutine 与判定共进程的四宗债：裸 goroutine 无 recover（panic 互杀）、GC/连接池共享、单副本假设（worker 无消费组、定时循环无防重）、重启互相牵连。
> **已拍板口径（2026-09-23 用户确认）**：
> ① **方案 1「跟随主服务、独立进程」**——同镜像多 workload，不建独立服务（拆包是下一站，不是本轮）；
> ② **自实现同步、不接任务平台**——快慢分治：秒/分钟级 duty loop（事件/巡检/TTL 回收）与判定状态机紧耦合必须进程内自治；天级深对账是批任务，已开 `POST /sync/reconcile` 标准 API 供任务平台/任何人经网关调度；
> ③ Go 侧无语言级进程管理——**容器编排即进程管理器**（12-factor 单进程容器模型，比照 Python supervisord 的位置）；
> ④ 企业级演进线单口径：单实例标配 → 双 workload 隔离（本轮）→ 消费组+锁多副本（本轮一并具备）→ 规模触发拆独立服务。

## 三、验收标准

1. **隔离**：`kill -9` 任一进程不影响另一进程存活与服务（demo 期间做一次 iam-sync 宕机注入：判定照常、fresh_age 老化进 Degraded、重启后恢复 Fresh）。
2. **panic 防护**：临时注入 `panic("x")` 于 patrol 循环体 → 进程存活、后续轮次继续（日志有 recover 记录）——验证后还原。
3. **双副本防重**（S3/S4/S5 联合实证）：`--scale iam-sync=2` 下 XINFO GROUPS 消费者=2、单活锁同一周期仅一执行者、水位单调、demo 22 场景全绿。
4. **构建**：`make backend-image GOARCH=amd64` 一次出镜像，双二进制可执行。
5. **前端零改动**（纯后端+部署）；`go build ./... && go vet ./... && go test ./...` 全绿。

## 四、风险与边界（明确不做什么）

| 项 | 决定 | 说明 |
|-|-|-|
| 独立服务/独立镜像 | **不做**（下一站） | 拆包 = 搬 main 入口，本轮两 main 包结构已为其铺路 |
| 任务平台接管同步 | **不做** | 快慢分治已拍板：duty loop 自治保判定正确性；批任务走 `POST /sync/reconcile` API（既有事实，B 层文档补口径 S9-⑤） |
| 手动同步 API 转发队列给 sync 进程 | **不做** | 低频管理操作留 API 进程直调；并发安全由幂等三道门+S5 CAS 兜底（R2） |
| 审计事件 Streams 化 | **维持设计目标** | 与本清单无关，§5.9 既有注记不动 |
| **R1 锁周期与时长** | 锁 TTL = 周期/2 必须 > 单轮耗时 | demo 快败路径（拒连/DNS）毫秒级 ✓；**边界（审查 L-3）**：上游黑洞故障 + 启用契约数×10s HTTP 超时（4 域≈40s）> demo 锁 TTL 2.5s → 双副本接管双跑——幂等兜底，**验收 3 的"单活"判定加适用前提"快败路径"**；单轮耗时超 TTL 80% 打 warn；reconcile 锁 TTL 独立分钟级 |
| **R2 手动 API 与后台循环并发** | 同表写并发 | upsert 三道门+单调守卫+S5 水位 CAS 已覆盖；S4 锁**只锁后台循环**不锁手动 API（设计如此，不改） |
| **R3 消费组毒消息** | 处理持续失败的消息会无限被 claim | 认领次数上限（如 5 次）→ 投递 `cmdb-events:dlq` 死信流 + 告警日志 |
