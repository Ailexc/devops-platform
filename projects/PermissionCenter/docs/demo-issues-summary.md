# 演示系统问题总结

> **日期**：2026-08-08
> **状态**：待修复
> **相关文件**：`frontend/src/views/DemoPlay.vue`、`frontend/src/components/demo/` 下所有组件

## 一、布局与交互问题

### 问题 1：双重进度条

**现象**：演示页面同时存在两个进度指示器：
1. 左侧步骤侧栏（StepSidebar）：显示步骤列表 + 圆点进度
2. 底部控制栏（PlayerControls）：显示 `1 / 7` 进度条 + 圆点

**期望**：只保留一个进度指示，另一个改为其他信息展示（如场景描述、快捷键提示等）。

**建议方案**：
- 方案 A：移除底部进度条，只保留侧栏步骤列表
- 方案 B：移除侧栏步骤列表，只保留底部进度条
- 方案 C：侧栏改为场景信息（描述 + 快捷键），底部保留进度条

### 问题 2：缺少返回目录按钮

**现象**：演示全屏后，侧栏被隐藏，没有「返回目录」的入口。用户只能通过浏览器后退或手动改 URL 回到目录页。

**期望**：演示模式下应有明显的「← 返回目录」按钮。

**建议方案**：
- 在播放器顶部或底部添加「← 返回目录」按钮
- 按 `ESC` 键返回目录（已在 `onKeydown` 中实现，但按钮不可见）

### 问题 3：演示全屏后侧栏隐藏无过渡

**现象**：进入演示模式时，侧栏突然消失，没有过渡动画，体验突兀。

**期望**：侧栏有收起/展开的过渡动画。

**建议方案**：使用 CSS `transition` 或 Vue `<Transition>` 组件实现平滑过渡。

## 二、内容准确性问题

### 问题 4：权限市场「应用授权申请」描述不准确

**现象**：`PermMarketScreen.vue` 中「应用授权申请」描述为"鉴权方式 + 网络打通"，但实际系统中这个概念可能不完全对应。

**期望**：需要确认系统中「应用授权」的真实含义，确保演示内容与系统能力一致。

**建议**：与实际系统功能对齐后修正描述。

### 问题 5：系统概览步骤 3「应用管理」与步骤 4「打包能力」割裂

**现象**：应用注册和能力发布被拆成两个独立步骤，但实际操作中它们是连续的工作流。

**期望**：考虑合并为一个步骤，或在步骤间增加过渡说明。

## 三、技术问题

### 问题 6：mock-screen 内容宽度不随窗口缩放

**现象**：部分屏幕组件的内部内容使用固定 `max-width`（如 `400px`），窗口放大时内容不跟随扩展。

**已修复**：将 `max-width` 改为百分比（如 `40%`），但可能仍有遗漏。

**待检查**：所有屏幕组件的内部容器是否都已改为百分比宽度。

### 问题 7：浏览器缓存旧 CSS

**现象**：修改 CSS 后浏览器仍显示旧样式，需要手动清缓存。

**已修复**：nginx 添加 `Cache-Control: no-cache` 头。

**待验证**：是否所有静态资源都已设置 no-cache。

---

## 四、UI/UX 问题

### 问题 8：演示模式无沉浸感

**现象**：虽然已隐藏侧栏和 topbar，但演示内容本身没有全屏沉浸感（如全屏按钮、暗色背景等）。

**期望**：演示模式应有更强的沉浸感，类似 PPT 全屏播放。

**建议方案**：
- 添加全屏按钮（调用 `requestFullscreen` API）
- 暗色背景 + 大字体
- 动画过渡更流畅

### 问题 9：步骤侧栏在小屏幕上显示不全

**现象**：当浏览器窗口较小时，步骤侧栏的文字可能被截断或溢出。

**期望**：侧栏在小屏幕上应自适应（如只显示数字编号）。
