## 一、为什么改（背景与依据）

### 1.1 触发：03 文档评审暴露的五个缺口

03-PermissionCenter 技术梳理初稿评审时，用户连续提出五组问题，逐组讨论收敛后发现：现有 Demo 设计与文档在"数据如何进入权限中心"这条链路上存在系统性缺口。五个缺口与讨论结论：

| # | 用户提出的问题 | 讨论收敛结论 |
|-|-|-|
| 1 | 架构图看不懂：三条鉴权路径（接口/数据/程序间）在图上完全不可见 | 主架构图须以**鉴权路径为骨架**，组件摆位退居其次；图内聚焦视角改路径名 |
| 2 | 有权限校验时直接去查外部数据源不行吗？同步进来的数据怎么抄、抄到哪、多久过期？ | 直查不可行（可用性/延迟/压力/数据形态四理由）；**副本无 TTL（靠同步收敛）、缓存才有 TTL**；云管直读与权限投影是同一数据源的两种场景化策略 |
| 3 | 能力包的接口维度与数据维度什么关系？校验时匹配的数据源是接口返回的数据还是 CMDB 的数据？ | 能力包=**声明非数据**；**判定链路与消费链路分离**——判定读 IAM 侧投影（真相源是权威源、读取位置在 IAM），消费走发布方接口透传 |
| 4 | OpenAPI 拿到的一定是发布方自家模型（普遍规律）；申请时的实例数据从哪来？"接口给 A 数据、范围引用 B 数据"会不会落空？ | 自家模型成立（**防腐层**）；实例身份**归发布方命名空间**（业界 Zanzibar/AWS 同口径）；申请选择器读 IAM 投影（PIP）；配对错位被三层机制拦成 **fail-closed 拒绝**（判少可修，判多才是事故） |
| 5 | 中间层/投影代理？指纹契约（勾选数据级验证必须设指纹字段）？三元素（新增/删除/更新）可判定性是发布方成本？鉴权时能不能复用指纹判断本地投影有问题→回源真实判定？ | **全部成立，业界有直接对应物**（见 1.3）；唯一修正：指纹比对不进每请求热路径，鉴权三档化（默认本地 fail-closed / 后台巡检同步 / 高风险 force-remote 回源） |

### 1.2 现状盘点（Demo 现有实现与缺口）

**已有基础**（代码实证修正版，代码真身在 `backend/` 下；**施工纪律：所有落点必须带 `backend/` 前缀**——项目顶层 `cmd/`、`internal/` 是不可构建的游离残留，照字面施工必落错目录，feature 分支顺手清理）：

- `backend/internal/sync/`：三个独立 struct（OpenAPISyncer / CMDBConnector / IdentityConnector，**无共享接口抽象**）；现状通道 = **手动 HTTP 触发的全量同步**（`POST /api/v1/sync/cmdb`）+ seed 种子 + 事件 upsert（worker XRead 消费 mock-cmdb 的 `cmdb-events` 流）——**"定时调度器"在全 backend 不存在，A4 需从零建**（可仿 `cmd/iam-server/worker.go` 模式）
- `backend/internal/openfga/`：OpenFGA 适配（WriteAuthorizationModel / Write / Check / ListObjects），关系数据物化在 OpenFGA 自有 datastore；**tuple 格式约定 = `model.Code:ExternalID`**（`dataplane.go:57`），A5 清理按此生成删除对象
- `resource_models` / `resource_instances` 投影表（`backend/internal/model/resource.go`，GORM AutoMigrate 零手写 SQL），带 `synced_at` 水位；**⚠️ 关键缺口：上游 updated_at 未进投影表**——连接器 upsert 时丢弃 CMDBInstance.UpdatedAt，而 A1 fp / A4 水位 / A5 漂移检测全部以"上游时间戳可比对"为前提，**A1 动工第一步 = 补 `upstream_updated_at` 列 + 连接器映射**
- **能力包预设已有 `data_control` / `data_models` 字段**（`model/capability.go:78-95` + `handler_capability.go:838-841` 校验 data_control=true 必填 data_models）——A2 的"勾选数据级验证"有现成载体，挂在这条已有校验链上，不新造概念
- `model/policy.go:20` Policy.ForceRemote 标记存在且已是 action 级消费（bundle 动作码列表 → agent 比对命中 relayRemote）；**但数据级判定路径完全不读 force_remote**（`handler_authz.go`/`dataplane.go` 无钩子），A6 需新增分支
- `decision_logs` 表与 `Reason` 字段已存在（`model/audit.go:16-29`），现有值域 = action denied / data engine unavailable / openfga check，查询端点现成（`GET /decision-logs`）；**注意：`internal/audit/` 包不存在**（architecture.md §8 误列），审计/决策日志现状 = goroutine 直写 PG
- Redis Streams：**仅 CMDB 事件一路真实闭环**（mock-cmdb XAdd → iam-server worker XRead）；"审计事件走 Streams 两用"是 §5.9 设计目标、现状未落地；另 worker 用 XRead "$" **无 consumer group**，iam-server 扩多副本会重复消费（upsert 幂等危害小，B1 文档须注明）
- §7.3 "agent 无 bundle/包过期 → 回源中心 check" 的降级先例（本轮鉴权三档是它的同构扩展）；测试基础良好：`make test`（go test ./...）+ `scripts/demo.sh` 10 场景（场景 9 已是"CMDB 宕机仍鉴权"雏形，降级演示扩它即可）
- **mock-cmdb 限制**（A3/A4 验收设计必须规避）：纯内存存储、重启即 seed 且 seed UpdatedAt=进程启动时刻 → 演示期间重启 mock-cmdb 会造成全表假变更洪水；**处置：seed 时间改固定基准值 + 演示变更一律走 API + 演示期间不重启 mock**

**缺口清单**（本轮改造的直接对象）：

| # | 缺口 | 后果 |
|-|-|-|
| G1 | 无增量水位通道：同步只有"定时全量" | 同步成本随数据量线性膨胀，无法高频巡检 |
| G2 | 无指纹机制：不知道数据变没变 | 每次同步全写库；无从判断投影是否陈旧 |
| G3 | 无记录级 fp：无法定位差异、无法写库去重 | 重复 upsert 浪费；深对账无法区分"哪条新增/删除/更新" |
| G4 | 接入方义务未契约化：注册应用不要求任何数据字段保证 | 上游静默变更（直接改库、时间戳不动）漏检；新鲜度责任悬空 |
| G5 | 申请选择器数据来源未规范成文 | 实现碰巧读投影，但没有契约约束，后续改动可能破坏"申请不依赖外部系统在线" |
| G6 | 三发布方场景（数据提供方与发布方错位）未显式化 | 文档讲不清"云管发布能力包但数据是 CMDB 的"这类业务事实 |

### 1.3 业界依据（论证：这不是野路子）

| 本方案设计点 | 业界对应物 | 说明 |
|-|-|-|
| 指纹契约（注册期声明字段+算法义务） | **Data Contract（数据契约）**运动；SCIM 2.0 强制每资源带 `meta.lastModified`；IMAP/CalDAV sync-token（同步令牌）协议级义务 | "契约义务化"业界有据（SCIM/sync-token 是协议实现义务）；**"注册期强制+拒绝发布"没有外部锚点，是本平台基于 fail-closed 红线（判多是事故）的产品决策**——按自家红线辩护，不硬攀业界 |
| 数据指纹脏检（先比指纹再决定拉不拉） | HTTP **ETag/If-None-Match**（实体标签/条件请求）；K8s `resourceVersion`（资源版本号）；DNS SOA serial（域名区域序列号）；GitOps 声明哈希 | 一族成熟实践，形态完全同构 |
| 集合指纹失配 → 二段定位差异 | **rsync quick check**（先比大小+mtime，不一致才深比） | 两段式经典实现 |
| 投影代理层（专做数据投影的中间层） | **CDC→读侧投影**（变更数据捕获→投影，贴切对应）；OPA bundle builder（策略包构建管道，对应偏松、仅思想同源）；各 IAM 标准化 Connector 框架 | Demo Sync Service 的标准化演进形态 |
| 鉴权失配时本地数据不足的降级续判 | CDN stale-while-revalidate（过期边用边刷新）——**仅对应 2.3 降级分支①（不可达→最后已知数据+warning）**；默认档"缺记录→拒绝"与 SWR 方向相反，不得用 SWR 为三档全称背书；本项目 §7.3 agent 降级回源是同构先例 | 降级分支①有业界对应；默认档 fail-closed 是安全侧自有决策 |
| 发布方责任制（数据新鲜度归发布方） | 数据工程原则 "producer owns data quality"；Google Zanzibar：客户端负责写关系数据，Zanzibar 只负责又快又对地判 | 权限中心不兜底外部数据 |
| 凭证托管（发布方给凭证、IAM 代查申请选择器） | **Vault 式密钥管理 / Secret Manager 静态托管 + 代理查询实践**（注意：不是 Vault "动态凭据"——那是运行时按需签发短时效凭据，与本方案"注册时提交静态只读凭证、长期托管"语义不同，面试勿答错）；云控制台申请表单实时列资源（接口契约四件套：端点/认证/过滤/分页） | 解决"申请人对目标资源零权限"的鸡生蛋问题 |
| 实例 ID 归发布方命名空间 | Zanzibar tuple `资源类型:资源ID#关系@主体`；AWS ARN / GCP 资源 URI——均引用发布方自有 ID，无中央资产库假设 | "锚点换主人"而非"锚点消失" |
| 三元素（新增/删除/更新）责任归发布方 | 本平台自有决策（依据=生产者负责数据质量原则 + 同步问题本质就是三态；**无单一业界产物可锚**）；发布方保证字段可算出确定性指纹，IAM 只出算法菜单 | 若算不出→**出路成文**：不勾数据级、只做接口级发布（数据级本就是可选深度）——"注册期拒绝"定性为自家红线决策（见 1.3 表注） |

### 1.4 用户拍板的口径原则（全文档通用）

1. **发布方负责数，权限中心负责判**——数据新鲜度 SLA（服务级别约定）归发布方；判定正确/可用/快速/可审计归权限中心。权限中心可以自己做缓存与加速，**不为任何上游数据兜底**。
2. **判定链路与消费链路分离**——判定读 IAM 侧（本地投影 + OpenFGA 关系），永不实时依赖外部；消费走发布方接口（业务数据透传）。两链路共享真相源、互不依赖。
3. **副本与缓存要分清**——资源投影是副本不是缓存：无 TTL，靠事件+增量持续覆盖、源端删除级联清理收敛；有 TTL 的只是决策缓存层。
4. **判少可修、判多是事故**——一切配对/数据问题的失败方向必须是 fail-closed（拒绝），配合审计与定期审阅兜底。
5. **能力包是声明不是数据**——接口清单 + 数据范围引用（scope 引用指向数据域，数据本身不进包）。
6. **接口与数据是两个维度、两条链路**——接口级永远必选；数据级是可选深度（有的能力包只做接口级鉴权，无需投影）。
7. **最小权限凭证**——发布方托管给 IAM 的凭证只读、限定在声明的数据模型范围内，进密钥管理，永不进判定路径。
8. **术语分域（防两套叫法，两文档并读口径）**——**视图 = 云管域**（读侧呈现，真实=直读不落副本）；**投影 = 权限中心域**（判定数据副本，同步收敛语义）——同一权威源的两种本地化产物，**禁止互换**；主词定"**数据契约（Data Contract）**"，"指纹契约"=其指纹义务部分（字段+算法档位+新鲜度承诺）的通称；**对账三兄弟**：资源对账（02，CMDB vs 云资源）/ 深对账（03，IAM 投影 vs 权威源）/ 财务对账（不接）——03 机制一律称"深对账"；"本地"首现括注（本地=权限中心侧投影，区别于网关 agent 的边缘本地）；"回源"=从边缘低延迟层回到权限中心中心判定，**上游/发布方永不作为判定主体出现**（详见 2.3 消歧）；禁词沿用 02 惯例（正文不出现"读模型"，统一用"投影/视图"分域表述）。

## 二、目标架构（改完之后的样子）

### 2.1 总体结构：投影代理层（Sync Service 标准化形态）

```
能力发布方（云管 / CMDB / 自有数据平台 / …）
  │  接入义务三级（数据契约）：
  │  L1 必须：查询接口带 updated_at + updated_after 增量过滤
  │  L2 推荐：数据变更事件推送（webhook / 写入 API）
  │  L3 可选：指纹查询端点（表级版本号 / 集合哈希）
  │  勾选数据级验证 → 必填指纹契约（字段 + 算法档位 + 新鲜度承诺）
  │
  ▼
┌───────────────────── IAM 投影代理层（Sync Service 标准化）─────────────────────┐
│  Connector 框架（三通道统一编排）                                                │
│  ├─ 事件快通道（秒级）：webhook/写入 API → Redis Streams → upsert               │
│  ├─ 指纹巡检通道（分钟级）：定时集合指纹脏检 → 失配→增量拉（水位回拨重叠窗口）     │
│  └─ 深对账通道（天级）：全量拉 → 三类差异（更新 / 孤儿清理 / fp 漂移）            │
│  记录级 fp：投影表 fp 列（判定字段规范化 JSON 哈希）→ 写库去重 + 差异定位         │
│  集合指纹：按发布方指纹契约算法（L1 count+max(updated_at)                        │
│           / L2 hash(ID集合)⊕hash(updated_at集合) / L3 判定字段全量哈希）         │
└───────────────────────────────────┬──────────────────────────────────────────┘
                                     ▼
        ┌─────────────── IAM 数据面（判定层，本方案不变）───────────────┐
        │  PG 投影表（resource_models/instances + fp + synced_at）       │
        │  OpenFGA 关系数据（自有 datastore，tuple 用发布方资源 ID）      │
        │  Redis（策略/决策缓存 TTL + 资源热索引）                        │
        └─────────────────────────────────────────────────────────────┘
```

**配套的关键模型变化**：

- **两层身份显式化**：接口权限点 = 发布方自家模型语义（OpenAPI → 权限模板，防腐层产物，如 `cm:instance:list`）；实例身份 = 发布方命名空间的资源 ID（投影 external_id / OpenFGA tuple 的资源 ID）。判定、申请、scope 翻译全部使用第二层身份。
- **数据契约成为注册期模型（主词：数据契约；"指纹契约"=其指纹义务部分通称）**：`data_contracts` 表——app_id + model + fields（字段）+ algorithm（L1/L2/L3）+ staleness_sla（新鲜度承诺）+ enabled；**载体复用既有字段**："勾选数据级验证"挂在能力包预设已有的 `data_control`/`data_models` 校验链上（`handler_capability.go:838-841`），不新造概念；勾选数据级的**能力包发布必填**，注册时跑试算自检；**自检失败语义二分**：发布方端点不可达 → 提示稍后重试（不计入契约拒绝，注册是控制面操作、调外部符合既有 Sync 设计）；字段算不出三元素确定性指纹 → 拒绝发布 + 给算法建议 + **出路话术**（"不勾数据级、只做接口级发布"）。staleness_sla 是 A6 超龄判定的读参来源（A2 依赖链：A6→A2→A3 端点）。
- **各算法档位的静默变更检测延迟矩阵**（面试可主动讲盲区=懂行）：发布方绕过触发器直接改库、updated_at 不动时——L3（判定字段全量哈希）= 分钟级可检；L1（count+max）/L2（集合哈希）= **指纹全盲**，唯一兜底 = A5b 深对账天级全量 fp 漂移检测；无深对账 = 永不。Demo 由 mock 模拟触发器口径，真实对接是发布方 DB 层义务，**违约由深对账兜底**（不是注册期自检能防的——注册时只能验证"当前样本算得出指纹"）。
- **凭证托管（演进项，非本轮必做）**：发布方注册时提交只读最小权限凭证（进 Secret Manager 静态托管+代理查询——**非 Vault 动态凭据语义**），IAM 代查申请选择器所需资源目录——契约四件套（端点/认证/过滤/分页）。Demo 阶段申请选择器直接读 IAM 投影即可，凭证代查列为演进方向写入口径。

### 2.2 申请链路新口径（判定链路 · 申请阶段）

```
申请人（对目标资源零权限——正因没权限才来申请）
  → PAP 申请表单：资源选择器数据 = IAM 本地投影（resource_instances）
     ├─ 理由①鸡生蛋：申请流程不能依赖申请人已有的权限
     ├─ 理由②解耦：申请/审批不依赖发布方系统在线
     └─ 理由③最小暴露：选择器只需要判断字段，不搬运业务数据
  → 审批（资源 owner，风险分级）→ 策略发布（版本化）→ OpenFGA/Casbin 写入
  →（可选演进）发布方数据获取接口声明 + IAM 凭证代查
```

申请表单实例数据**不调发布方接口、不拉真实业务数据**——读 IAM 投影（即术语表 PIP 策略信息点，判定与申请两环节共用同一份同步数据）。**代码实证（2026-09-21 核查）**：`Marketplace.vue` → `api.instances()` → ResourceRepo 直查本地投影表，全程无 mock-cmdb 调用——**A7"大概率已是"升级为"已证实"**，此项只剩口径固化。**新鲜度窗口口径（必写）**：新资源刚创建、投影未同步到的窗口期，申请人选择器里选不到（甚至手动输入 ID 提交，开通锚点仍需实例入投影）——演示前先触发一轮同步；生产可演进"手动输入 external_id + 审批时后台校验"，但**读投影换解耦，代价就是分钟级新鲜度窗口**——这句话面试主动讲，化被动为主动。

### 2.3 鉴权链路三档（判定链路 · 执行阶段）

| 档位 | 行为 | 适用 | 依据 |
|-|-|-|-|
| **默认档** | 权限中心本地投影判定（本地=权限中心侧，区别于网关 agent 的边缘本地）+ **记录级 fail-closed**：check-instance 查投影缺该实例记录 → 拒绝该条请求，决策日志 reason=data_missing；**fail-closed 精确化**：它挡的是"记录缺失"（代码现状：OpenFGA 无 tuple 已天然 deny、引擎报错已 503，新增≈reason 区分+超龄检查）；**挡不住"记录在、属性旧"**——属性陈旧时用旧部门/旧标签判定存在**分钟级最终一致窗口内的判多暴露面**，靠巡检收敛 + 审计 + 强一致档收窄（面试话术见附录 6，不遮掩）。**filter（列表）降级语义（拍板 A 方案）**：陈旧窗口内返回旧允许实例集 + 响应体 stale 标注（与审计/Trace 联动）；超龄则转 deny | 所有普通请求的热路径 | 解耦原则：判定永不实时依赖外部 |
| **巡检兜底档** | 后台指纹巡检（分钟级，持续跑）：集合指纹失配 → 触发增量同步 + 告警 + 决策日志标注"数据陈旧"（reason=stale） | 数据新鲜度保障（不在请求线程里） | 指纹比对进后台不进热路径（用户方案的正确摆放） |
| **强一致档（force-remote，原名"风险回源档"更名）** | 高风险动作（action 打 force-remote 标记，与 §5.7 同一标记合流）→ 指纹快查 →（若变更）触发**前置同步** → **IAM 以同步后的最新投影判定**（强一致）→ 后台同步补偿。**措辞红线：判定主体永远是权限中心，上游/发布方永不判定**——业务系统"零权限代码"口径由此不破；"回源"在本档指"判定前强化数据新鲜度"，**标记复用是真的（Policy.ForceRemote 已存在且已是 action 级消费），但数据级挂接的行为（请求路径指纹快查+前置同步）是本轮新增**，面试如实讲"复用同一标记、数据级行为新增" | 高风险写操作 | §5.7 force-remote 拓扑回源的**数据新鲜度同构扩展**；代码事实：数据级路径现无钩子，需在 handler_authz/dataplane 新增分支 |

**降级策略（拍板：优先级显式化，两分支不再打架）**：

1. **上游不可达（指纹端点超时/宕机）→ 可用性优先**：按本地最后已知数据判定 + 决策日志 warning + 告警；**降级时限可配置**（degrade_max_age，如上游连续不可达超 N 小时后升级为 deny）——"上游挂了权限不能挂"在时限内成立，超时限安全优先。
2. **系统健康但数据超龄（staleness_sla 超龄）→ 数据质量优先**：deny，**粒度 = 仅该数据域的数据级判定**（接口级与其它数据域不受影响）；**开关可配置**（对齐 §5.7 agent 降级"可配置 fail-open 或回源"的治理深度，数据级默认永不 fail-open，但开关存在供演练/紧急豁免）。
3. **优先级规则**：不可达分支优先于超龄分支生效（上游挂了先降级续判，不因超龄叠拒）；两态都可配。
4. **禁止**鉴权请求等待上游指纹响应（每请求依赖外部=解耦失败）；fail-open 分层口径：fail-open 仅是边缘 agent 的可配置项（Demo 默认仍 fail-closed），**数据判定路径永不 fail-open**。

**"回源"三义消歧（03 文档术语表同款）**：① 02 的"回源权限中心 PDP"= 业务系统 → IAM（调权限中心判定）；② §5.7 的"回源中心"= 网关 agent → 中心 PDP（边缘路由回中心）；③ 数据级档位**不叫回源**，叫"前置同步判定/强一致档"——三个"回"里上游系统永不作为判定主体。

### 2.5 三种发布方场景对照（文档显式化，消除"数据提供方冲突"困惑）

## 附录：讨论沉淀的面试收束话术（修订版，03 文档定稿后同步进 interview-narrative，同步时按"全局验收"清单一并修正 narrative 既有"读模型"残留与补三句）

1. **数据同步**："鉴权是每请求热路径，实时查外部=外部挂全平台瘫，所以判定数据必须本地化：事件快通道+指纹巡检对账+深对账三通道同步，副本无 TTL 靠收敛、缓存才有 TTL，降级时 synced_at 水位可见——数据多新是可观测的。"
2. **能力包双维度**："能力包=接口清单+数据范围声明，声明不是数据；判定链路读 IAM 投影、消费链路走发布方接口，共享真相源互不依赖——所以发布方和数据提供方是谁，不影响发布也不影响校验。"
3. **数据契约**（主词修订）："勾选数据级验证必须签数据契约：指纹字段+算法档位+新鲜度承诺，三元素（新增/删除/更新）可判定性是发布方成本；集合指纹管拉不拉、记录 fp 管写不写；IAM 出算法菜单不兜底数据。业界对应=ETag/K8s resourceVersion/DNS SOA 一族；**注册期拒绝是我们的 fail-closed 红线决策**（业界只到义务化）——算不出指纹的发布方走接口级发布，数据级本就是可选深度。"
4. **鉴权三档**（措辞修订）："默认**权限中心本地投影**判定 fail-closed（缺数据拒单条，判少可修判多是事故）；后台指纹巡检失配触发同步+告警；高风险动作走**强一致档**——force-remote 标记与策略分发合流，判定前指纹快查+前置同步，**判定主体永远是权限中心，上游系统零权限代码、永不判定**。指纹永远不在普通请求的热路径上。"
5. **发布方责任制**（补状态机三态）："发布方负责数（新鲜度 SLA/事件推送/数据契约），权限中心负责判（正确/可用/快速/可审计）；我们做缓存和加速，但不为任何上游数据兜底。降级三态可观测：缺数据→fail-closed 拒单条；数据旧但未超新鲜度承诺→降级续判+warning+告警（上游不可达时可用性优先，降级时限可配）；超承诺或超时限→deny（粒度限该数据域数据级判定）。"
6. **属性陈旧与判多面**（新增，防追问弹药）："fail-closed 挡的是记录缺失；记录在、属性旧时存在分钟级最终一致窗口的判多暴露面——这不是漏洞是边界：靠巡检收敛+决策日志审计+高风险档前置同步收窄窗口，所有判多面在审计里可查、可回溯。filter 场景陈旧窗口返回旧集合+stale 标注，超龄才拒——列表语义与单点语义分开设计。"
7. **同步机制对照**（新增，防 02/03 串台）："同步思想同构（本地化+增量+事件）：云管视图=定时全量+事件**双通道**；权限中心=**三通道**（多指纹巡检+深对账）——判定 fail-closed 对数据质量要求更高，故多两层收敛。对账三兄弟别搞混：资源对账（云管域，CMDB vs 云资源）、深对账（权限中心域，IAM 投影 vs 权威源）、财务对账（不接）。"
