一、项目整体背景与目标

企业上云后普遍面临 多云资源分散、口径不一、成本失控、操作不可审计 四大问题。 Cloud Manager 定位为统一的多云资源管理平台（CMDB 为核心），目标是：

  • 统一纳管：AWS / 阿里云 / 腾讯云等异构云资源统一建模、统一视图。
  • 操作可控：所有变更操作走工单审批，全程留痕可审计。
  • 成本可见：账单按部门 / 应用分摊，配合规则引擎持续优化。
  • 数据一致：CMDB 为唯一数据源，云、工单、成本均以 CMDB 为准。

二、原有系统能力与短板

业务范围

覆盖资源纳管、工单审批、操作审计、成本管理、服务目录等核心能力。

原有系统短板

  • 多云控制台割裂，无统一视图与统一建模。
  • 操作无统一审批流，无法追溯责任。
  • 成本无分摊，无法回答"谁在用、用了多少"。
  • 数据源多头，云上状态与内部 CMDB 常不一致。

三、Demo 系统建设诉求

  • 架构还原：还原真实项目的四层架构与核心设计决策。
  • 业务闭环：申请 → 工单 → 审批 → 执行 → 回写 CMDB 端到端打通。
  • 亮点突出：依赖图谱、成本规则引擎、场景模板、数据权限等。
  • 演示友好：全量 Mock 数据 + 可配置规则 + 系统演示模块。

四、核心诉求总结

一句话：用 CMDB 唯一数据源，把多云资源、工单审批、成本分摊打通成一个可解释、可演示、可复盘的闭环系统。
