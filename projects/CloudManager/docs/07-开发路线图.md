# 07 · 开发路线图

> 分 4 个阶段落地，每阶段有可演示的产出，边做边巩固，随时可面试演示。

## 阶段总览

| 阶段 | 主题 | 核心产出 | 可演示亮点 |
|---|---|---|---|
| P1 | 架构还原 | 前端 + 后端 + 工单 + CMDB 骨架，单云（Mock/AWS）资源管理 | 跑通"申请→审批→执行→回写"最小闭环 |
| P2 | 多云适配 | 云适配层 + AWS/阿里云/Mock Provider + 统一资源模型 | 真正"多云"，多云资源统一展示 |
| P3 | 业务闭环 | 服务目录自服务 + 权限审计 + CMDB 深化 | 完整业务闭环 + 权限隔离 + 审计留痕 |
| P4 | 亮点冲刺 | 成本管理 + 智能资源建议 | FinOps 降本故事 + 优化建议清单 |

## P1 · 架构还原（最小闭环）

**目标**：跑通四层架构的端到端流程。

- [ ] 后端多模块工程初始化（Spring Boot + MyBatis-Plus + MySQL + Redis + RabbitMQ）
- [ ] 数据库建表（CMDB 核心表 + 工单表 + 用户/角色表）
- [ ] Mock Provider：内置主机/网络/安全组模拟数据
- [ ] 工单流程引擎：创建→审批→执行→完成 状态机
- [ ] 前端框架搭建：仿 AWS 控制台布局，计算模块（主机列表 + 状态管控 + 规格变更 + 申请 + 下线）
- [ ] CMDB 同步：Mock Provider 数据同步 + 操作回写
- [ ] Docker Compose 一键启动

**验收**：在页面完成一次"申请主机→审批→自动交付→列表可见"的完整操作。

## P2 · 多云适配

**目标**：真正具备"多云"能力。

- [ ] 定义 `CloudProvider` 统一接口（纳管/查询/操作/账单）
- [ ] SPI 插件化注册机制
- [ ] AWS Provider（AWS SDK v2）
- [ ] 阿里云 Provider（阿里云 SDK）
- [ ] 统一资源模型：EC2/ECS、VPC/VPC、安全组统一抽象
- [ ] 多云资源统一列表与筛选（按云/地域/状态）
- [ ] 账单查询接口（为 P4 铺路）

**验收**：一套页面同时管理 AWS 与阿里云（Mock）资源，新增云只加 Provider。

## P3 · 业务闭环

**目标**：完善企业级能力。

- [ ] 服务目录：申请模板 + 配额管理 + 自助申请
- [ ] 权限体系：RBAC 功能权限 + 部门数据权限
- [ ] 操作审计：AOP 注解 + 审计查询页
- [ ] CMDB 深化：资源关系建模 + 变更历史 + 拓扑视图

**验收**：不同角色登录看到不同数据与功能；所有操作有审计记录；拓扑图可查看资源关系。

## P4 · 亮点冲刺

**目标**：面试差异化亮点。

- [ ] 成本中心：模拟账单生成器 + 成本趋势 + 部门分摊 + 预算告警
- [ ] 智能资源建议：规则引擎（闲置/低效检测）+ 优化建议清单 + 预估节省金额
- [ ] 整体 UI 打磨 + 演示数据脚本
- [ ] 面试文档完善（[06-面试准备.md](06-面试准备.md)）+ 演示录屏

**验收**：完整演示脚本跑通，可对外演示。

## 每阶段结束检查项

- [ ] 新增代码有注释与关键设计说明（便于复盘）
- [ ] 能口头讲清本阶段每个模块的设计与取舍
- [ ] 面试文档（06）同步更新对应问答
- [ ] Git 提交，保留阶段里程碑

## 技术要点备忘（开发中重点关注）

- 云操作幂等（request_id 去重）
- 工单状态机（防并发状态错乱）
- 数据权限统一过滤（避免漏拼条件）
- Mock 数据生成器（可配置规模，演示效果好）
- 前端资源列表大数据量分页 + 缓存
