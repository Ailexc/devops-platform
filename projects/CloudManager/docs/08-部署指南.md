## 二、CI/CD 流程

### GitHub Actions 工作流

1. **触发条件**
   - 推送到 `main` 或 `develop` 分支
   - Pull Request 到 `main` 分支

2. **测试阶段**
   - 后端测试：Django 单元测试
   - 前端测试：ESLint + TypeScript 检查 + Vitest 单元测试

3. **构建阶段**
   - 构建前端生产版本
   - 上传构建产物

4. **部署阶段**
   - `develop` 分支 → 部署到 GitHub Pages Preview
   - `main` 分支 → 部署到 GitHub Pages Production
   - `main` 分支 → 构建 Docker 镜像并推送到 GitHub Container Registry

### 工作流文件

- **位置**: `.github/workflows/deploy.yml`
- **功能**: 自动化测试、构建、部署

## 三、本地部署

### 前置条件

- Docker Desktop
- Docker Compose
- Git

### 快速开始

```bash
# 1. 克隆代码
git clone <repository-url>
cd cloud_manager

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env 文件配置数据库密码等

# 3. 构建前端
cd frontend && pnpm install && pnpm build && cd ..

# 4. 运行部署脚本
./deploy.sh

# 5. 访问应用
# 前端: http://cloud-manager-nginx.orb.local
# 后端: http://cloud-manager-backend.orb.local/api/
```

### 手动部署

```bash
# 1. 构建前端
cd frontend && pnpm install && pnpm build && cd ..

# 2. 构建并启动
docker compose -f docker-compose.yml up -d --build

# 3. 查看日志
docker compose -f docker-compose.yml logs -f

# 4. 停止服务
docker compose -f docker-compose.yml down
```

## 四、服务配置

### 服务端口

| 服务 | 端口 | 说明 |
|------|------|------|
| Nginx | 不暴露 | 通过 OrbStack 域名访问 |
| MySQL | 不暴露 | 容器内通信 |
| Redis | 不暴露 | 容器内通信 |
| Backend | 不暴露 | 容器内通信 |

### 服务访问

| 服务 | OrbStack 域名 |
|------|---------------|
| 前端 | `http://cloud-manager-nginx.orb.local` |
| 后端 API | `http://cloud-manager-backend.orb.local/api/` |

### 环境变量

详见 `.env.example` 文件，主要配置：

- `MYSQL_ROOT_PASSWORD`: MySQL root 密码
- `DJANGO_SECRET_KEY`: Django 密钥
- `DJANGO_ALLOWED_HOSTS`: 允许的域名

## 五、监控与日志

### 查看服务状态

```bash
# 查看所有服务状态
docker compose -f docker-compose.yml ps

# 查看特定服务日志
docker compose -f docker-compose.yml logs nginx
docker compose -f docker-compose.yml logs backend
docker compose -f docker-compose.yml logs mysql
```

### 健康检查

```bash
# 检查后端健康状态
curl http://cloud-manager-backend.orb.local/api/

# 检查数据库连接
docker compose -f docker-compose.yml exec mysql mysqladmin ping -h localhost
```

## 六、备份与恢复

### 数据库备份

```bash
# 备份数据库
docker compose -f docker-compose.yml exec mysql mysqldump -u root -p cloud_manager > backup_$(date +%Y%m%d).sql

# 恢复数据库
docker compose -f docker-compose.yml exec -T mysql mysql -u root -p cloud_manager < backup.sql
```

### 数据卷备份

```bash
# 备份 MySQL 数据卷
docker run --rm -v cloud_manager_mysql_data:/data -v $(pwd):/backup alpine tar czf /backup/mysql_data.tar.gz /data

# 恢复 MySQL 数据卷
docker run --rm -v cloud_manager_mysql_data:/data -v $(pwd):/backup alpine tar xzf /backup/mysql_data.tar.gz -C /
```

## 七、常见问题

### 1. 端口被占用

```bash
# 查看占用端口的进程
lsof -i :80
lsof -i :3306

# 停止占用端口的服务
sudo lsof -ti :80 | xargs kill -9
```

### 2. 数据库连接失败

```bash
# 检查 MySQL 是否正常运行
docker compose -f docker-compose.yml ps mysql

# 查看 MySQL 日志
docker-compose -f docker-compose.yml logs mysql
```

### 3. 构建失败

```bash
# 清理 Docker 缓存
docker system prune -a

# 重新构建
docker compose -f docker-compose.yml build --no-cache
```

## 八、生产环境建议

1. **安全配置**
   - 使用强密码
   - 启用 HTTPS
   - 配置防火墙

2. **性能优化**
   - 启用 Redis 缓存
   - 配置 CDN
   - 优化数据库查询

3. **监控告警**
   - 配置日志收集
   - 设置性能监控
   - 配置告警通知

4. **定期维护**
   - 定期备份数据库
   - 清理无用日志
   - 更新依赖版本
