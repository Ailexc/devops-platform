# 04 · 技术选型

## 一、选型前提（硬约束）

**技术栈必须与真实工作经历一致**，这是保证面试可信度的硬约束。
以下为国内企业内部多云管理系统的常见组合，供对照确认；最终以实际经历为准。

## 二、选型建议

| 层 | 建议选型 | 备选 | 说明 |
|---|---|---|---|
| 后端 | **Java + Spring Boot** | Go | 国内企业最普遍；Spring 生态（Spring MVC/MyBatis/RabbitMQ）与工单、CMDB 场景契合 |
| 前端 | **Vue 3 + Ant Design Vue** | React + AntD | 易于实现仿 AWS 控制台风格；Vue 国内生态最主流 |
| 数据库 | **MySQL** | PostgreSQL | 业务数据存储，符合国内企业内部系统惯例 |
| 缓存 | **Redis** | — | 资源列表缓存、分布式锁、任务队列辅助 |
| 消息队列 | **RabbitMQ** | Kafka | 异步工单/任务状态通知，轻量够用 |
| ORM | **MyBatis-Plus** | Spring Data JPA | 国内主流，开发效率高 |
| 云 SDK | **AWS SDK v2、阿里云 SDK** | — | 多云适配层对接 |
| 认证 | **Spring Security + JWT** | Sa-Token | 登录鉴权 + RBAC |
| 构建 | **Maven** | Gradle | 多模块构建 |
| 部署 | **Docker Compose** | — | MySQL/Redis/RabbitMQ + 前后端一键启动 |

## 三、关键选型理由

### 后端：Java + Spring Boot
- 与国内企业多云管理/工单/CMDB 类系统的主流技术栈一致
- 多模块化便于"云适配层 + Provider"的插件化设计
- 生态成熟，面试可聊点多（AOP 审计、Spring Security、RabbitMQ 集成）

### 前端：Vue 3 + Ant Design Vue
- Ant Design 组件丰富（表格/表单/树/抽屉），还原 AWS 控制台风格的资源列表、详情、操作面板效率高
- 配套 Vue Router + Pinia + Axios 为前端标配，面试沟通成本低

### 消息队列：RabbitMQ
- 工单状态变更、异步任务通知场景足够
- 相比 Kafka 更轻量，符合"内部管理系统"的体量定位（也如实反映真实场景）

### 云 SDK
- AWS SDK v2（异步 + 同步）与阿里云 SDK 对接统一适配接口
- Demo 阶段可提供 **Mock Provider**（模拟云），保证无真实云账号也能完整演示

## 四、Mock 策略（Demo 关键设计）

真实云操作在演示环境不可用，需要 **Mock Provider**：
- 实现同一套 `CloudProvider` 接口
- 内置资源数据生成器（主机/网络/安全组等）
- 模拟异步任务（延迟 + 状态推进），完整还原"申请→审批→执行→回写"链路
- 成本模块使用**模拟账单生成器**（生成可信的月度账单分布）
- 面试沟通时如实说明"Demo 使用 Mock 数据模拟云，真实项目对接真实云 SDK"

## 五、暂缓/排除项

- 分布式微服务全套（Nacos/Sentinel/Gateway）—— 内部管理系统单体多模块即可，避免过度设计
- 容器化 K8s 部署 —— Docker Compose 足够
- 重量级开源 CMDB/工单 —— 自建轻量实现更贴合"内部自研"人设
