# P6 · 应用中心（组织树/环境切片）与场景绑定

**目标**：把应用中心从"资源管理"中独立出来，形成"组织 → 应用 → 环境 → 依赖"的业务视角；
场景模板不再作为孤岛入口，而是绑定到应用环境（业务场景）与资源（运维场景）上下文中。

**状态**：✅ 已实施（2026-08-06，含完整模拟数据）

---

## 一、设计决策

### 1. 应用中心 = 业务视角（与资源管理区分）

| 维度 | 资源管理（运维） | 应用中心（业务） |
|---|---|---|
| 操作对象 | 云资源 | 应用/环境 |
| 入口 | 云主机/网络/拓扑 | 组织树 → 应用 → 环境 |
| 典型操作 | 启停/变配/下线 | "给订单中心生产环境扩容" |
| 数据 | 同一元数据视图 | 同一元数据视图 |

- 底层数据不变（CMDB/整合视图单一事实源），只换导航与操作语言
- 权限收口：数据权限按组织 → 应用 → 环境维度隔离

### 2. 环境 = 一等公民（部署切片）

- 新增 `cmdb.Environment`：应用下 dev/test/staging/prod，绑定云账号 + 地域
- 服务实例 `environment` 外键；资源 `environment` 可空外键（直接归属环境的资源）
- 同一应用不同环境：资源依赖形态不同（dev 无数据库依赖，prod 有 RDS/缓存/消息队列）

### 3. 场景 = 绑定层（不孤立）

- 业务场景：挂在环境详情页，自动带入 org/app/env 上下文
- 运维场景：挂在资源详情页，自动带入资源 ID/类型上下文
- 执行一律提交工单系统（场景工单 SO 前缀，审批后编排执行）
- 条件步骤：`skip_if_missing` 缺参自动跳过（如从安全组上下文发起时无实例可绑定）
- 编排方式采用"预定义模板 + 参数化"，自由编排列为演进方向（参照蓝鲸标准运维）
