## 第二阶段：演讲演示模块开发（5天）

> **目标**：开发独立的「系统演示」演讲模块，像 PPT 一样逐步展示系统能力  
> **核心原则**：先宣讲后操作 —— 用预编排的演讲流程展示全流程，面试官感兴趣再切到实际功能  
> **交互方式**：鼠标点击前进/后退，不自动播放，结束后返回主目录  
> **验收标准**：6个演讲场景可在15分钟内完整演示，过渡丝滑、无报错

### 设计理念

```
传统演示：  "我来操作一遍给你看"  →  紧张、容易出错、漏看细节
演讲模式：  "请看系统全景" → 逐步展示 → 亮点高亮 → 结束返回
                  ↓
            面试官感兴趣？→ [跳转到实际功能] → 现场操作
```

### 架构设计

```
侧边栏新菜单："🎬 系统演示"
    │
    ├── 演示目录页（场景卡片列表）
    │
    └── 演示播放器（核心组件）
        ├── 步骤指示器（○ ○ ● ○ ○）
        ├── 内容区域（路由跳转 + 浮层高亮）
        ├── 说明卡片（标题 + 亮点文字）
        ├── 导航按钮（上一步 / 下一步 / 返回目录）
        └── 进度条
```

## 五、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 路由跳转后高亮定位不准 | 演示效果差 | 使用 CSS 固定定位 + 数据属性选择器，逐步调试 |
| 页面加载慢导致步骤卡顿 | 演示不流畅 | 预加载下一跳转目标，loading 状态处理 |
| 浮层遮挡关键内容 | 看不到重点 | 高亮区域留白 + 浮层智能定位（上下左右自适应） |
| 场景数据过多导致维护困难 | 改一处要改多处 | 统一数据结构，每个步骤独立配置 |
| 审批中心复杂度高 | 开发超期 | 简化为列表+通过/驳回按钮，不做复杂流程 |
| 申请主机弹窗字段多 | 开发超期 | 只保留核心字段：规格/地域/网络 |
