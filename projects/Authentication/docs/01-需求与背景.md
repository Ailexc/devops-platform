# 统一认证中心（Authentication）— 需求与背景

> 还原真实工作中「统一门户 + 登录认证 + SSO 多系统统一访问」经验的 Demo 系统。

## 一、项目背景

`DevOpsPlatform` 目录下存在多个并行开发的子系统（`CloudManager`、`WorkFlowCenter`、`EventManager`、`ReleaseManager`、`TaskManager`、`PermissionCenter`），早期为并行开发方便，每个系统**各自维护独立的登录机制**。

但在真实生产环境中，这些系统统一共享一套登录机制，用户只需在**统一门户**登录一次，即可无感知访问所有已授权应用。本项目的目标就是把这种能力在 Demo 里还原出来：

- **统一门户**：承担所有业务系统的入口，展示「应用广场」，点击即达
- **登录认证中心**：统一校验用户名 / 密码，签发跨系统共用的凭证
- **SSO 单点登录**：一次登录，多系统统一访问

## 二、真实项目参考（面试叙事）

> 以下为真实工作项目中的做法，本 Demo 以此为目标还原。

```
用户 → EAA 平台 → 统一门户
         │
         ▼
      Okta 认证（外部身份源）
         │ 通过
         ▼
   平台认证服务（校验用户名/密码）
         │
         ▼
    下发 JWT Token（多系统共用）
         │
         ▼
   统一门户 → 应用广场 → 各业务系统直接访问
```

- 认证方式：**支持两种**——以 **Okta 作为身份源**验证，**支持降级到 LDAP** 认证
- 凭证：认证通过后下发 **JWT Token**，在多个系统之间共用
- 网关 / 权限中心健全，Token 全程统一可用

## 三、本 Demo 的定位与约束

| 维度 | 说明 |
|------|------|
| 用途 | ① 复盘巩固知识点 ② 面试项目演示 ③ 知识点学习 |
| 形态 | 前后端分离 |
| 能力 | 统一门户 + 登录认证 + SSO 多系统统一访问 |
| 认证源 | Okta（OIDC）/ LDAP / 本地用户库，**可配置切换 + 自动降级** |
| 前端 | React 19 + Ant Design（统一门户） |
| 后端 | Python + FastAPI（认证中心） |
| 接入 | 统一网关 forwardAuth（Traefik）演示统一鉴权 |

> ⚠️ Demo 环境**没有真实 Okta / LDAP**，因此采用「身份源抽象层 + 降级链」方案：
> - **LocalAuthenticator**（默认，零依赖）：本地用户库 + bcrypt 校验，跑通 SSO 主链路
> - **LdapAuthenticator**：连接 OpenLDAP 容器（Docker），真实 LDAP bind 认证
> - **OktaAuthenticator**（预留）：OIDC 授权码流，Demo 中由 mock OIDC 或文档说明承接

## 四、非目标（明确不做）

- 不负责各业务系统内部的功能逻辑
- 不实现 EAA 平台（用户从真实环境已认证进入，此处用文档说明 + 可选的 mock 入口模拟）
- 不做真实的 Keycloak / Okta 云服务对接（成本与 Demo 定位不符）
