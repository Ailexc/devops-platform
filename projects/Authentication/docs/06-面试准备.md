# 统一认证中心 — 面试准备

## 一、项目叙事线（30 秒电梯陈述）

> 我在真实工作中接触过一套企业级统一认证体系：用户通过 EAA 平台进入统一门户，门户背后的认证服务以 Okta 为身份源校验用户，并支持降级到 LDAP；认证通过后签发跨系统共用的 JWT，用户即可无感访问门户里所有已授权应用。我基于这段经验复刻了一个前后端分离的「统一门户 + 认证中心 + SSO」Demo：身份源抽象层支持本地库 / LDAP / Okta 三种实现并可自动降级；RS256 JWT 通过 JWKS 发布公钥供异构系统验签；Traefik 网关用 forwardAuth 做统一鉴权。

## 二、核心亮点

1. **身份源抽象 + 降级链**：`Authenticator` 策略模式，`Okta → LDAP → Local` 自动 failover；区分「认证失败」（不降级）与「身份源不可用」（降级），守住安全边界
2. **统一凭证 RS256 JWT + JWKS**：非对称签名，公钥发布，异构系统本地验签，无回源
3. **统一网关 forwardAuth**：鉴权下沉网关，业务系统配置级接入，零代码
4. **统一门户 + 应用注册表**：应用注册表驱动门户应用广场，新应用注册即上架

## 三、高频问题与应答要点

### Q1：为什么不用 Session，而用 JWT？
- Session：服务端存储、可主动失效、但跨系统/跨域共享麻烦、扩展需共享 session 存储
- JWT：无状态、天然适合**多系统共享**与**水平扩展**，签名防篡改
- 代价：无法服务端主动作废 → 用 refresh token + 黑名单/Redis 白名单补足

### Q2：HS256 和 RS256 的区别？为什么选 RS256？
- HS256：对称密钥，签发/验签同一把密钥，密钥不能分发到多系统
- RS256：非对称，私钥签发、公钥验签；公钥可安全分发，多系统独立验签，支持 JWKS + 密钥轮换

### Q3：什么是 JWKS？怎么轮换密钥？
- JWKS = JSON Web Key Set，`/.well-known/jwks.json` 发布公钥集合（含 kid）
- 轮换：签发新密钥对 → 新 token 用新 kid → 保留旧公钥一段时间（验签时按 kid 查）→ 全部过期后移除旧公钥

### Q4：降级链怎么保证安全？为什么认证失败不降级？
- 只有「身份源不可用」（连接超时、服务宕机）才触发降级
- 「用户不存在 / 密码错误」是明确失败，降级等于给攻击者开了一道通往弱身份源的后门
- 降级与失败均写入审计日志（记录实际认证 source）

### Q5：JWT 泄露怎么办？
- 缩短有效期（如 1h）+ refresh token 机制
- 传输全程 HTTPS；登录页防 XSS（CSP、不把 token 放 localStorage 可减少 XSS 面，Demo 放内存 + HttpOnly cookie 更安全）
- 关键操作二次校验；网关层可做 IP/设备指纹绑定

### Q6：LDAP 认证的原理？
- 两步：服务账号搜索用户 → 得到 DN → 用用户 DN + 密码 bind；bind 成功即密码正确
- 优势：不直接传输明文比对、利用 LDAP 目录权威数据、天然支持组织架构

### Q7：业务系统怎么接入？改动量大吗？
- 统一网关 forwardAuth 模式：业务系统**配置级接入**，把入口挂到网关后面，网关校验 JWT 并注入 `X-Auth-*` 头，业务后端读头即可
- 无网关的系统：加一个 JWT 验签中间件（各语言 jose 库 + 认证中心 JWKS 公钥），约几十行

### Q8：OAuth2 授权码模式和 OIDC 区别？
- OAuth2 管「授权」（给第三方应用发访问令牌），不管「你是谁」
- OIDC 在 OAuth2 之上加 `id_token`（JWT 身份断言），解决「认证 + 身份传递」
- 企业 SSO 通常 = OIDC（授权码 + PKCE）

### Q9：单点登出（SLO）怎么做？
- JWT 无状态，SLO 是难题；方案：认证中心维护会话 + 通知各业务系统撤销，或各系统轮询/共享黑名单
- Demo 中先做「门户登出 + 撤销 refresh token」，SLO 列为扩展项

## 四、可能的追问深挖点

- 多租户 / 组织架构如何建模？
- 权限怎么和 `PermissionCenter` 协同？（认证给「身份」，权限中心给「授权」，职责分离）
- 高可用：认证中心无状态 + 共享 DB/Redis，网关水平扩展
- 审计合规：登录来源、失败原因、身份源来源全部落审计日志
