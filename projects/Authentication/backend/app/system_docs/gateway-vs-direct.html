要回答的核心问题

一个业务系统接入统一认证，最常问的就是：走网关还是不网关？这两条路都依赖"统一 JWT"（认证中心签发的 RS256 签名令牌），区别在于谁来做验签、以及业务系统要不要写鉴权代码。

核心区别

维度经网关（forwardAuth）不经网关（直连 JWKS）
请求路径客户端 → 网关 → 业务后端客户端 → 业务后端（不经网关）
谁验签网关转发给认证中心验签业务后端本地拉公钥验签
业务鉴权代码零，读注入头即可需实现一次验签中间件
认证中心宕机请求被拦（网关验签失败）已发 token 仍可验（高可用）
性能多一次内部 HTTP 转发本地验签，更快
管控能力网关统一限流/审计/拦截各自为政
适合场景网关能覆盖的内部应用外部部署/跨网络/网关覆盖不到

经网关接入的链路

  1. 用户访问业务系统，请求头带 Authorization: Bearer <统一JWT>；
  2. 网关（Traefik forwardAuth）拦截请求，转发给认证中心验签；
  3. 验签通过后，网关注入 X-Auth-User / X-Auth-Username / X-Auth-Name / X-Auth-Source 头放行；
  4. 业务后端零鉴权代码，直接读注入头就知道当前用户。
# 业务后端读取注入的身份头（示意）
user   = request.headers.get("X-Auth-Username")
source = request.headers.get("X-Auth-Source")
# 无需自己验签，网关已经保证请求是可信的

不经网关（直连）接入的链路

  1. 用户直接访问业务系统，请求头带统一 JWT；
  2. 业务后端从 /.well-known/jwks.json 拉取公钥（缓存）；
  3. 本地验 RS256 签名 + 有效期 + iss/aud；
  4. 通过后从载荷读用户身份。

怎么选

业务系统在网关后面？→是：经网关接入→零鉴权代码
业务系统在网关覆盖不到（外部/跨网络）？→直连 JWKS 验签→实现一次验签中间件

补充：标准 OIDC 客户端接入（授权码 + PKCE）是另一条独立的"协议级"路径，适合需要完整用户会话与标准协议的第三方系统，见《OIDC 客户端接入指南》。

统一 JWT 的角色说明

重要：统一 JWT 是本项目内部链路的凭证（门户应用广场经 sso-url 签发、网关/直连验签），属于 Demo 场景下对"真实企业 SSO 跳转"的模拟。门户自身的登录走的是标准 OIDC 授权码 + PKCE，两者解耦、职责不同。

小结

  • 经网关：网关统一验签 + 注入身份，业务零代码，适合网关覆盖范围。
  • 直连：本地拉公钥验签，无回源、高可用，适合网关覆盖不到。
  • 选择依据：系统是否在网关后面、是否愿意维护验签中间件。
