一键启动

项目用 Docker Compose 编排全栈，在 OrbStack（或任意 Docker 环境）下执行：

# 构建全部镜像并启动
docker compose build
docker compose up -d

# 查看容器状态（应 7 个 Up）
docker compose ps

# 查看认证中心启动日志（确认建表 + 种子就绪）
docker logs authentication-auth-backend

Compose 服务

docker-compose.yml 中 COMPOSE_PROJECT_NAME=authentication，容器名前缀为 authentication-。服务清单：

服务说明
auth-backend认证中心（OIDC Provider）+ 门户 BFF，端口 8002
portal门户前端（React + nginx），端口 5175
traefik统一网关，端口 28001/28080/8004
oidc-demoOIDC 客户端演示，端口 8005
mock-app经网关接入演示，端口 8081
direct-app直连 JWKS 验签演示，端口 8003
pilot-app试点接入模板，端口 8004
openldap（可选）LDAP 身份源，需 --profile ldap 启用
lam（可选）LDAP 可视化管理界面（LDAP Account Manager），端口 8083，随 --profile ldap 启用；登录：用户 cn=admin,dc=devops,dc=com / 密码 adminpass

关键环境变量

# .env（compose 自动读取）
COMPOSE_PROJECT_NAME=authentication   # 项目名/容器前缀
AUTH_PROVIDER_ORDER=ldap,local         # 身份源顺序（LDAP 优先，本地库兜底）
AUTH_PROVIDER_LOCAL_ENABLED=true      # 本地身份源启用
AUTH_PROVIDER_LDAP_ENABLED=true       # LDAP 身份源默认启用

# 认证中心容器内
DATABASE_URL=postgresql://devops:devops@devops-postgres:5432/devops_auth

认证中心的核心配置默认值（config.py）：issuer = auth.devops.orb.local、audience = devops-portal、算法 RS256、access_token 1 小时、refresh_token 7 天、OIDC 授权码 5 分钟一次性。

外部数据库依赖

认证中心依赖外部共享库 devops-postgres（不在本 compose 内）。启动顺序：

  1. 数据库容器先就绪（devops-postgres 健康）；
  2. auth-backend 通过 wait_for_db.py 等待数据库可达；
  3. 启动时执行 ensure_schema()（迁移）→ create_all()（建表）→ seed_all()（种子数据）。

常见问题

现象原因与处理
auth-backend 一直 Restarting数据库不可达或 schema 报错。先确认 devops-postgres 健康，再 docker logs authentication-auth-backend 看具体错误
column xxx does not exist老库缺新列。migrate.py 已自动补齐；若手动排查可用 psql 核对表结构
经 localhost 访问 OIDC 元数据端口异常nginx 反代 + Starlette base_url 推导问题，用 OrbStack 域名（portal.authentication.orb.local）访问即正常；BFF 跳转不受影响
改代码不生效需要重新 docker compose build <服务> && docker compose up -d <服务>

小结

  • docker compose build && up -d 一键全栈，7 容器 + 外部共享库。
  • 身份源默认 LDAP 优先（本地库兜底），LDAP 相关服务经 --profile ldap 启用。
  • 数据库迁移/种子自动执行，日志可追溯。
