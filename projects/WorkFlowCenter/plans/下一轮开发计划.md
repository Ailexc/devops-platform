## 二、P0 — 阻塞性 Bug 修复

### 2.1 流程设计器节点配置持久化 🔴

**问题**：审批人/条件/抄送人等节点配置保存后丢失。

**排查路径**：

```
抽屉组件（ApproverDrawer 等）
    ↓ 用户编辑配置，点击确认
flowStore.flowDefinition.nodeConfig（内存状态）
    ↓ 用户点击"保存草稿"
buildPayload() → definition_json（已修复，从 flowStore 读取）
    ↓ PUT /api/v1/process-definitions/:id/
后端 definition_json 字段
    ↓ 再次打开编辑页
initDefinition() ← props.modelValue（从后端加载）
    ↓ 传给 ProcessFlowDesigner
flowStore.setFlowDef()
```

**验证清单**：

| # | 验证点 | 操作 | 预期结果 |
|---|--------|------|---------|
| 1 | 抽屉配置写入 flowStore | 编辑审批人 → 点确认 → 检查 flowStore | 节点配置已更新 |
| 2 | buildPayload 输出完整性 | 保存草稿 → 检查 PUT 请求体 | definition_json 包含节点配置 |
| 3 | 后端存储完整性 | GET 流程定义 → 检查 definition_json | 数据完整保存 |
| 4 | 回显完整性 | 重新打开编辑页 → 流程建模步 | 节点配置正确回显 |

**修复策略**：
1. 浏览器控制台验证：抽屉编辑后检查 `flowStore.flowDefinition`
2. flowStore 正确 → 问题在 buildPayload（已修复，需验证）
3. flowStore 不正确 → 抽屉 onConfirm 未更新 store，需修复
4. 回显不正确 → initDefinition 或 JSON 解析问题

**子项验证**：
- [ ] 审批人节点：指定具体用户 → 保存 → 回显
- [ ] 审批人节点：指定角色 → 保存 → 回显
- [ ] 审批人节点：或签/会签切换 → 保存 → 回显
- [ ] 条件网关：添加条件表达式 → 保存 → 回显
- [ ] 条件网关：多分支 → 保存 → 回显
- [ ] 抄送人节点：指定抄送人 → 保存 → 回显
- [ ] 办理人节点：绑定能力 → 保存 → 回显
- [ ] 完整流程保存后全部回显

**预估工时**：1 天

## 七、系统宣讲模式（Slide Engine）

### 7.1 设计理念

> **痛点**：现场操作紧张容易翻车，时间短任务重，背功能亮点太累。
> **方案**：把产品演示做成可交互的 Slide Deck，预置数据 + 截图 + 自动播放，像 Windows 初始化一样引导观众。

## 八、演示流程设计

### 8.1 流程总览

| # | 流程名称 | Key | 发起方式 | 审批链路 | 自动执行 |
|---|---------|-----|---------|---------|---------|
| 1 | 申请服务器 | `server_apply` | **程序 + 人工** | 运维审批 → 自动开通 | Mock 开通主机 |
| 2 | 申请新增服务 | `new_service_apply` | **仅人工** | 部门主管 → 运维开通 | Mock 部署服务 |
| 3 | 服务器重启 | `server_restart` | **仅程序** | 无需审批 → 自动重启 | Mock 重启主机 |

### 8.2 流程 1：申请服务器（程序 + 人工发起）

**表单字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| hostname | input | 主机名 |
| cpu | inputNumber | CPU 核数，默认 4 |
| memory | inputNumber | 内存(GB)，默认 8 |
| os | select | 操作系统（CentOS 7 / Ubuntu 22.04 / Windows 2022） |
| reason | textarea | 申请理由 |

**流程链路**：

```
┌────────┐    ┌──────────┐    ┌──────────┐    ┌──────┐
│ 发起人  │───→│ 运维审批  │───→│ 自动开通  │───→│ 结束  │
│ 提交    │    │ (IT运维) │    │ (Mock)   │    │      │
└────────┘    └──────────┘    └──────────┘    └──────┘
```

### 8.3 流程 2：申请新增服务（仅人工发起）

**表单字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| service_name | input | 服务名称 |
| service_type | select | 服务类型（Web / API / 消息队列 / 数据库） |
| environment | select | 部署环境（测试 / 预发 / 生产） |
| resource_request | textarea | 资源需求描述 |
| reason | textarea | 申请理由 |

**流程链路**：

```
┌────────┐    ┌──────────┐    ┌──────────┐    ┌──────┐
│ 发起人  │───→│部门主管  │───→│ 运维开通  │───→│ 结束  │
│ 提交    │    │ 审批     │    │ (Mock)   │    │      │
└────────┘    └──────────┘    └──────────┘    └──────┘
```

### 8.4 流程 3：服务器重启（仅程序发起）

**表单字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| hostname | input | 主机名 |
| reason | textarea | 重启原因 |

**流程链路**（最简版）：

```
┌────────┐    ┌──────────┐    ┌──────┐
│ 发起人  │───→│ 自动重启  │───→│ 结束  │
│ (程序) │    │ (Mock)   │    │      │
└────────┘    └──────────┘    └──────┘
```

### 8.5 能力绑定

| 流程 | 办理节点绑定能力 | Mock 行为 |
|------|----------------|----------|
| 申请服务器 | `cmdb.create_host` | 返回主机 ID + IP + 状态 |
| 申请新增服务 | `mail.send` | 返回 message_id |
| 服务器重启 | `cmdb.create_host` | 返回重启成功 |
