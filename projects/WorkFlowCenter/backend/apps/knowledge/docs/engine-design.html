流程引擎设计

一、设计目标

让「人工审批」与「系统自动执行」在同一张流程图上无缝衔接：审批人点一下，后面的建单、发通知、改状态等操作由引擎自动完成。

二、定义归一化

设计器产出的是 Beeflow 树形 nodeConfig（父子 + 条件分支），引擎无法直接遍历。因此先归一化为扁平结构：

nodeConfig(树)  →  normalized_definition  →  nodes[] + edges[]
nodes:  start / approve / cc / condition / gateway / handle / trigger / end
edges:  from → to（可带 condition，用于分支求值）

三、生命周期

阶段说明
start校验提单人权限 → 创建实例（记录发起）→ 推进到首个节点
advance按当前节点类型推进：审批/办理建任务、条件/网关求值跳转、结束完成实例
complete审批通过/办理完成 → 记录审批流水 → 推进下一节点（会签/或签单独处理）
reject / suspend / resume / terminate / delegate驳回终止、挂起恢复、撤销、转办

四、审批节点

  • 审批人解析：兼容 Beeflow 的 assigneeType（0发起人/1上级/2部门负责人/3角色/4指定/7自选）与引擎平铺 type 两种格式。
  • 多人审批：单人、会签（需全部同意）、或签（一人同意即通过）、序签。
  • 多渠道：审批人可通过 Web / Lark(飞书) 多渠道处理（演示环境模拟展示）。

五、办理节点（自动化的核心）

办理节点通过 taskConfig 声明动作，三种模式：

模式语义交互
manual人工办理生成待办，人处理
auto完全自动执行引擎直接调任务执行器跑动作，无人工参与
confirm自动执行 + 人工确认先生成确认待办，确认后执行动作

动作支持 串行 / 并行 编排，前序动作的输出可绑定到后续动作的入参，构成小的「自动化流水线」。
