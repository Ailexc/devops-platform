业务规则引擎

一、要解决的问题

提单前就要告诉用户「这张单能不能提、哪里不合规」：部门配额够不够、预算够不够、网段可达不可达、规格是否超配等。这些是业务规则，不是表单必填校验。

二、规则模型（结构化 AST）

规则不写死代码，而是结构化配置，每条规则包含：

rule = {
  id, name, level(error/warning),
  message,            // 命中提示
  suggestion,         // 处置建议
  groups: [[           // 条件组（组内 AND，组间 OR）
    { source: 数据源(表单字段/上下文指标),
      op: 操作符(>、<、==、in、contains…),
      refType: fixed | field,
      fixed: 固定值 | refField: 字段引用, offset: 偏移 },
  ]],
}

三、数据源

  • 表单字段：直接从 form_schema 提取（类型、枚举、区间），前端可下拉配置。
  • 上下文指标（可替换的数据层）：部门剩余配额、资源池容量、部门预算、预估月成本、网络可达段、历史同规格次数等。

四、判定与解释

  • 安全解释器：逐条走 AST 求值，不依赖 eval，杜绝注入。
  • 可解释：命中时返回 数据来源、左值、操作符、参考值、偏移、是否匹配，前端可逐条展示「判定明细」。
  • 双重防线：提单预检（提交前拦截）+ 提交复检（后端权威复检，error 级命中拒绝提交，防绕过）。

五、配置体验

规则在流程设计器第 4 步「业务规则」可视化配置：选数据源 → 选操作符 → 选参考值（固定值或字段引用），实时预览判定结果，无需写表达式。
