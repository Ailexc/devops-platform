# 权限模块实装开发计划

## 一、目标与范围

本计划将 Demo 中验证通过的权限模块交互与流程，落地到 React + Django 项目中。覆盖：组织权限树、我的权限、协作应用分享/申请/回收/解除、审批配置、审批中心。

## 二、Demo 沉淀的关键设计

### 2.1 权限属性分层

| 属性 | 说明 | 适用场景 |
|------|------|---------|
| 团队权限 | 通过归属组或协作组继承获得 | 组视图默认展示 |
| 个人权限 | 用户个人申请获得 | 生产环境特例、超出团队默认范围 |
| 混合权限 | 同一环境类型下，部分环境来自团队、部分来自个人 | 测试/预发等部分授权场景 |

### 2.2 环境选择模式

- **环境类型**：单选（dev / test / staging / prod）
- **具体环境**：同一类型下可多选
- 切换环境类型时自动清空已选具体环境

### 2.3 协作权限生命周期

```
分享协作应用  →  审批通过  →  对方获得协作权限
      ↑                              ↓
回收协作权限  ←  审批通过  ←  发起回收申请

申请协作应用  →  审批通过  →  本组获得协作权限
      ↑                              ↓
解除协作应用  ←  审批通过  ←  发起解除申请
```

## 三、数据库变更

### 3.1 模型调整

| 模型 | 变更 | 说明 |
|------|------|------|
| `BusinessLine` | 新增 `leader` FK → User | 业务线负责人 |
| `Group` | 新增 `leader` FK → User | 组负责人 |
| `ApprovalFlowTemplate` | 新建 | 可复用审批流模板 |
| `EnvironmentApprovalConfig` | 重构 | 按 `(env_type, grant_scope)` 配置，关联模板 |
| `PermissionRequest` | 新增字段 | `request_type`: share / apply / revoke / release |

### 3.2 `ApprovalFlowTemplate.steps` 结构

```json
[
  {
    "order": 1,
    "name": "应用负责人审批",
    "approver_resolver": "app_owner",
    "resolver_config": {},
    "required_count": 1,
    "timeout_hours": 24
  },
  {
    "order": 2,
    "name": "业务线负责人审批",
    "approver_resolver": "business_line_leader",
    "resolver_config": {},
    "required_count": 1,
    "timeout_hours": 48
  }
]
```

### 3.3 审批人解析策略

| 策略 | 说明 |
|------|------|
| `app_owner` | 应用负责人 |
| `group_leader` | 组负责人 |
| `business_line_leader` | 向上查找最近的业务线负责人 |
| `fixed_user` | 固定人员 |
| `fixed_role` | 固定角色组 |
| `parent_group_leader` | 上级组负责人 |
| `security_team` | 安全团队 |
| `ops_team` | 运维团队 |

### 4.3 API 接口（Phase 2）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/v1/org/business-lines/` | GET | 业务线列表（含负责人） |
| `/api/v1/org/business-lines/<id>/leader/` | GET | 查询业务线负责人 |
| `/api/v1/authz/approval-flow-templates/` | GET/POST | 审批流模板 CRUD |
| `/api/v1/authz/approval-flow-templates/<id>/` | PUT/DELETE | 审批流模板编辑/删除 |
| `/api/v1/authz/approval-strategies/` | GET/POST | 审批策略配置 CRUD |
| `/api/v1/authz/approval-strategies/<id>/` | PUT | 审批策略配置编辑 |
| `/api/v1/authz/calculate-approval-flow/` | POST | 动态计算审批流 |
| `/api/v1/authz/permission-requests/` | POST | 提交权限申请（分享/申请/回收/解除） |
| `/api/v1/authz/group-permissions/<id>/` | GET | 组权限详情 |
| `/api/v1/authz/user-permissions/<id>/` | GET | 用户权限详情 |
| `/api/v1/approvals/pending/` | GET | 我的待审批 |
| `/api/v1/approvals/<id>/approve-step/` | POST | 步骤通过 |
| `/api/v1/approvals/<id>/reject-step/` | POST | 步骤驳回 |

## 七、验收标准

### 7.1 功能验收

- [ ] 组织权限树能正确展示本组/协作/个人权限
- [ ] 个人权限环境详情能区分团队继承/个人申请/混合
- [ ] 分享协作应用支持“给组织”和“给指定成员”
- [ ] 申请协作应用支持“给本组”和“给指定成员”
- [ ] 回收协作权限仅在有组外协作人员时显示
- [ ] 解除协作应用仅在有授权环境时显示
- [ ] 所有协作类操作均触发审批流
- [ ] 审批中心能按类型筛选并进行步骤级审批

### 7.2 性能验收

- [ ] 组织权限树加载 < 1s（100 个节点以内）
- [ ] 审批流计算接口 < 300ms
- [ ] 权限申请提交 < 500ms

### 7.3 安全验收

- [ ] 权限申请只能由本人或负责人发起
- [ ] 审批操作需校验当前用户是否为步骤审批人
- [ ] 跨组协作权限范围不超出授权方配置

## 八、风险与注意事项

1. **数据迁移风险**：`EnvironmentApprovalConfig` 重构需兼容旧数据，建议先备份。
2. **审批流循环依赖**：向上查找业务线负责人时需避免循环父组链。
3. **前端状态管理**：分享/申请表单字段较多，建议使用 Form 组件统一管理验证。
4. **权限缓存失效**：审批通过后需触发 `rebuild_user_cache` 刷新缓存。
5. **成员选择边界**：申请给指定成员时，成员池必须来自当前组，不能从目标组读取。
