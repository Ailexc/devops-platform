# 权限管理面试题

## 普通

### RBAC 和 ABAC 的区别是什么？
RBAC 基于"角色→权限点"的静态映射，简单直观但权限点爆炸、粒度粗。ABAC 基于"主体属性+资源属性+环境属性"的动态策略评估，灵活细粒度但策略管理复杂。

### 为什么你们项目要从 RBAC 转向 ABAC-Lite？
经历了 v1 RBAC（权限点爆炸，几百个 API 手动勾选，漏配就报错）和 v2 权限模板后，发现核心痛点是"用户-权限点"的静态映射维护成本太高。ABAC-Lite 抛弃了权限点概念，改为动态评估。

## 进阶

### ABAC 标准四组件分别是什么？本系统如何对应？
PAP（策略定义）→ Policy 子类 + Rule 描述符；PDP（决策引擎）→ PolicyDecisionPoint 类；PEP（执行点）→ @require_permission 装饰器；PIP（属性源）→ BaseChecker + Django ORM。

### 为什么没有引入 OPA？
属性维度聚焦在组织关系链上，策略变更频率低，团队规模不大。OPA 的 Rego 语言学习成本高、部署运维复杂。

## 刁难

### 用户兼多角色时权限范围如何计算？
取并集。业务线负责人、组组长、组员身份的 accessible/manageable 集合合并后返回。

## 场景

### 推广到千人规模需要哪些改造？
引入缓存、策略迁移 OPA、PEP 下沉网关、审计日志、策略模拟器。
