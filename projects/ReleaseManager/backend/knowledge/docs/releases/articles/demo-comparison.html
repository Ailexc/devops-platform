Demo 实现对比

本文详细对比真实 Spug 发布系统与当前 Demo 系统在各方面的实现差异，帮助理解 Demo 系统的定位与能力边界。

1. 总体架构对比

对比维度 真实 Spug 系统 本 Demo 系统
技术栈 Python (Django) + React Python (Django REST Framework) + React + TypeScript
部署方式 主机 Agent 模式（SSH） 支持 EC2（SSH）和 K8s（kubectl）双模式
发布能力 5 种发布模式 7 种发布模式（含紧急发布、定时发布）
部署策略 基本滚动更新 6 种部署策略（滚动/蓝绿/灰度/重建/红黑/影子）
K8s 支持 不支持原生 K8s 集成 支持 K8s 原生操作（通过 k8s_client）
审批流程 基本审批 多级审批 + 紧急通道 + 定时发布
面试学习 运维实践 系统设计 + 部署策略 + 面试指南
定位 生产级运维工具 教学演示 + 面试准备系统

6. 如何启用真实 K8s 部署

💡 Kind 集群配置指南

Demo 系统支持通过 Kind (Kubernetes in Docker) 启动本地 K8s 集群，启用真实部署能力。以下为快速配置步骤：

  1. 安装 Docker — 确保本地已安装 Docker Desktop 或 Docker Engine
  2. 安装 Kind — 运行 brew install kind 安装 Kind
  3. 安装 kubectl — 运行 brew install kubectl 安装 kubectl
  4. 创建 Kind 集群 — 运行 kind create cluster --name demo-release
  5. 加载 kubeconfig — kind get kubeconfig --name demo-release > ~/.kube/config
  6. 验证连接 — 运行 kubectl cluster-info 确认集群状态
配置后效果
  • 发布流水线的部署阶段将真实操作 Kind 集群
  • 滚动更新策略通过 kubectl 真实操作 Deployment
  • 可以在 Kind 集群中查看 Pod 的创建和销毁过程
  • 发布历史记录反映真实的部署状态
  • 未配置 Kind 集群时，系统自动降级为模拟模式
