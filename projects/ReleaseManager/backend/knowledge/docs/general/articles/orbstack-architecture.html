3. 发布核心链路

1
用户提交发布单
前端 → Backend API → 创建 Release 记录 → 自动创建 Approval 记录
2
审批通过
审批人点击通过 → Backend 更新 Release 状态 → 触发执行
3
CI 构建 (docker build)
Backend → Executor API → docker build -t {app}:{version} → 镜像存入本地 Docker
4
CD 部署 (kubectl apply)
Executor → 生成 deployment.yaml → kubectl apply -f → 部署到 OrbStack K8s 集群
5
验证 & 完成
Executor → kubectl get pods 检查状态 → 更新 Deployment 历史 → 通知用户

4. Docker 容器 vs K8s 集群

维度Docker 容器 (发布系统自身)K8s 集群 (用户应用)
编排方式Docker ComposeKubernetes (OrbStack 内置)
网络local-net 共享网络K8s Service / ClusterIP
域名Traefik *.local 路由通过 NodePort 或 Ingress
存储Docker Volume (SQLite)K8s PV/PVC 或 emptyDir
生命周期随 docker compose 启停Deployment 管理，可滚动更新
镜像来源Dockerfile 构建docker build → K8s 拉取本地镜像
💡 关键点：OrbStack 的 Docker 和 K8s 共享同一个镜像存储。executor 用 docker build 构建的镜像，K8s 集群可以直接使用（无需推送到远程 Registry）。

5. Executor 的关键挂载

executor 容器是连接 Docker 和 K8s 的桥梁，通过挂载实现两种能力：

挂载路径来源用途
/var/run/docker.sock宿主机 Docker socket让 executor 能执行 docker build、docker tag 等命令
/app/config/kubeconfig~/.kube/config让 executor 能执行 kubectl apply、kubectl get pods 等命令
/demo-apps项目 demo-apps/ 目录提供应用源码（含 Dockerfile），供 docker build 使用
⚠️ 注意：docker.sock 挂载等同于授予容器完整的 Docker 控制权。这在本地开发环境是安全的，但在生产环境中需要严格限制权限（如使用 docker-socket-proxy）。

6. 域名规划

域名目标说明
release.localFrontend (Nginx)用户访问入口，Nginx 同时反代 /api/ 到 Backend
release-api.localBackend (Django)直接访问 API（调试用）
release-executor.localExecutor (FastAPI)查看 API 文档 /docs
traefik.localTraefik Dashboard查看路由规则和健康状态
💡 OrbStack DNS：所有 *.local 域名由 OrbStack 自动解析到 Traefik 网关，无需修改 /etc/hosts。只需在 Traefik 容器的 dev.orbstack.domains label 中注册即可。

维度本地开发 (dev.sh)Docker 部署 (docker-compose)
启动方式./dev.shdocker compose up -d
首次启动⚡ 快（直接运行）🐢 需构建镜像

8. 总结

本系统采用 Docker Compose + OrbStack K8s 的混合架构：

  • 发布系统自身运行在 Docker 容器中，由 Docker Compose 管理
  • 用户应用部署到 OrbStack 内置的 K8s 集群，由 Deployment 管理
  • executor 作为桥梁，通过 docker.sock 构建镜像，通过 kubeconfig 部署应用
  • Traefik 提供统一的 HTTP 入口，基于 Host 头路由到不同服务
  • 所有组件共享 local-net 网络，Docker 和 K8s 共享镜像存储

这种设计既保证了本地开发的便捷性（dev.sh 快速迭代），又提供了标准化的部署能力（docker-compose 一键启动），同时保留了真实的 CI/CD 链路（docker build → kubectl apply）。
