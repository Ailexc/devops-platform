# 01 · 项目需求与背景

## 一、项目整体背景与目标

本次计划开发一套**多云管理系统 Demo**，并非从零全新研发商用系统，核心依托过往真实工作中参与开发的多云管理系统经验进行**模拟复刻开发**。

Demo 主要用途：
1. 方便复盘、巩固相关技术知识点
2. 作为面试项目成果进行演示展示

**整体开发思路**：先还原历史真实项目架构与核心能力，再适度合理扩展功能。扩展尺度需要把控，不能过度虚构，避免面试沟通时容易被质疑识破；同时通过合理拓展，丰富项目亮点，提升面试竞争力。

## 二、原有真实项目概况

### 业务范围
- 系统命名为"多云管理系统"，但企业内部**主要使用 AWS 云资源**，实质上仅实现 AWS 资源管理
- 与市面上成熟多云平台存在明显差距

### 前端设计与能力
- 界面风格参考 **AWS 官方控制台**，按资源模块划分，无需切换外部页面即可查看、运维各类云资源
- 示例：计算模块统一展示云主机、网络、安全组、子网等资源信息
- 支持操作：主机状态管控、资源规格变更、新主机申请、主机下线等
- 定位：面向用户提供友好可视化交互入口，承接各类运维操作请求

### 后端架构与数据流
- 前端发起的所有操作请求，**后端不会直接执行**，而是**转发至内部工单系统**
- 工单系统承担：流程编排、审批流转、自动化任务执行能力
- 所有资源基础数据最终落地存储在 **CMDB 配置管理数据库**
- 云管前端展示的全部资源数据，**均从 CMDB 拉取加载**

### 原有系统短板
- 仅单一适配 AWS、无多云能力
- 整体功能较为单薄、场景有限
- 直接原样复刻作为面试项目，亮点不足、竞争力偏弱

## 三、Demo 系统建设诉求

1. **基础底线**：最大程度贴合原有真实项目架构、业务流程，保证整体技术方案符合过往真实工作经历，保证可信度
2. **优化目标**：在真实项目基础上，适度进行能力扩展，丰富项目内容，增加面试亮点
3. **约束条件**：新增扩展功能不能脱离技术现实、不可过度虚构，避免面试深度提问时出现漏洞
4. **需要协助**：分析、评估合理的扩展方向与落地范围，输出可行方案（见 [03-功能扩展方案.md](03-功能扩展方案.md)）

## 四、核心诉求总结

| 维度 | 诉求 |
|---|---|
| 可信度 | 架构与业务流程贴合真实经历，不穿帮 |
| 扩展性 | 适度扩展，丰富亮点，提升竞争力 |
| 真实性 | 扩展不脱离技术现实，可自圆其说 |
| 可落地 | Demo 规模可控，能真正跑起来用于演示 |
