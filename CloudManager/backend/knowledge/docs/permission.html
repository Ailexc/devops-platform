一、权限设计思路：去中心化 IAM

本项目不自建权限系统，而是接入 统一权限中心（Permission Center）：

  • 注册制：应用注册后发布"能力包"（菜单 / 操作 / 数据范围）。
  • 申请授权：用户按需申请能力包，审批通过后获得对应权限。
能力包数据范围可执行操作
全量管理员全部读 + 写 + 审批
部门负责人本部门读 + 申请
只读用户本部门只读

二、数据权限：后端强制过滤

Demo 做了简化：由后端按当前用户强制过滤数据范围，而非仅前端隐藏。

  • 超级管理员（admin） → 数据范围：全部。
  • 普通员工（readonly） → 数据范围：本部门（user.department）。
def _scoped_items(request):
    if request.user.is_superuser:
        return CostItem.objects.all()
    return CostItem.objects.filter(department=request.user.department)

应用在成本账单、优化建议、分摊、报告等所有接口，越权维度值自动清空。

三、为什么后端强制？

  • 前端控制可被绕过（改请求参数即可越权）。
  • 后端过滤是唯一可信边界，符合安全最佳实践。
  • 为对接真实权限中心预留：审批通过的能力包 → 数据范围映射。
