一、闭环链路

用户操作 → 生成工单(待审批) → 审批通过 → Provider 执行 → 回写 CMDB → 前端实时刷新

二、工单状态机

8 种状态：待审批 → 审批中 → 执行中 → 成功 / 失败，支持驳回、重提、关闭。

三、工单类型

  • 创建 / 启动 / 停止 / 变更 / 下线 / 关系变更（资源运维）。
  • 预算申请（apply_quota）：成本类工单，审批通过即更新预算。

四、关键机制

  • 统一入口：所有写操作（含场景模板、预算变更）都生成工单。
  • 审计留痕：操作记录 + 工单号 + 前后 diff 写入 audit / change 表。
  • 最终一致：执行结果异步回写，失败可重试 / 回滚。

五、为什么重要

工单闭环让"每一个变更都可解释、可追溯"，是运维平台区别于云控制台的核心价值，也是本项目面试演示的主线。
