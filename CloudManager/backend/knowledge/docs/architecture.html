一、总体架构：还原真实项目四层骨架

层级职责技术选型（Demo）
接入层Web / 用户交互Vue 3 + Ant Design Vue
业务层资源 / 工单 / 成本 / 权限Django REST Framework
流程层审批流 / 自动化任务工单系统 + Mock Provider
数据层唯一数据源CMDB（MySQL 8）

关键：所有数据以 CMDB 为唯一数据源，前端不直接操作云厂商，统一走后端 API。

二、核心设计决策（面试重点）

决策 1：操作为什么必须走工单系统？

  • 变更可控：所有写操作统一入口，未审批不执行。
  • 责任可溯：操作人、审批人、执行结果全程留痕。
  • 便于接入审计 / 合规要求。

决策 2：CMDB 为什么是唯一数据源？

  • 云上资源与内部数据一致，避免多头维护。
  • 支持跨云统一建模（多态资源表）。
  • 成本 / 拓扑 / 权限均基于 CMDB 数据派生。

决策 3：云操作是异步长任务，如何保证最终一致？

  1. 工单通过后提交到 Mock Provider 执行队列（真实系统为消息队列）。
  2. 执行结果异步回写 CMDB（采集 / 回写任务）。
  3. 失败可重试 / 回滚，保证最终一致。

三、云适配层设计（核心扩展点）

通过 Provider 适配层 屏蔽云厂商差异：

  • 统一操作接口（create / start / stop / resize / delete）。
  • 统一资源模型（Resource 多态 + 类型映射）。
  • 新增云厂商 = 新增一个 Provider 适配器，业务层无感。

四、数据流

查询链路（读）

前端 → /api/... → CMDB → 统一响应

操作链路（写）

前端 → 工单提交 → 审批通过 → Provider 执行 → 回写 CMDB → 前端刷新
