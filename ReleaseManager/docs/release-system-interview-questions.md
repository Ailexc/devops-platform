### 1.1 Python / Django 基础

#### Q1: Django ORM 中 `ForeignKey` 的 `on_delete` 参数有哪些常用选项？分别在什么场景使用？

**面试官视角**：考察候选人对 Django ORM 基础的掌握程度，是否理解级联删除的风险。

**候选人关注点**：
- `CASCADE`：级联删除，适用于强关联（如发布单与任务）
- `PROTECT`：阻止删除，适用于重要引用（如用户、组织）
- `SET_NULL`：置空，适用于可选关联（如回滚来源）
- `SET_DEFAULT`：设默认值
- `DO_NOTHING`：不操作（需手动处理，易出错）

**本系统示例**：
```python
# releases/models.py
rollback_from = models.ForeignKey('self', on_delete=models.SET_NULL, null=True, blank=True)
environment = models.ForeignKey(Environment, on_delete=models.CASCADE)
```

**扩展追问**：`on_delete=SET_NULL` 时字段必须设置什么？为什么？

#### Q2: Django REST Framework 中序列化器（Serializer）和模型序列化器（ModelSerializer）有什么区别？什么时候用哪个？

#### Q3: Django 的 `select_related` 和 `prefetch_related` 有什么区别？分别适用于什么场景？

**面试官视角**：考察候选人对数据库查询优化的理解，是否知道 N+1 问题。

**候选人关注点**：
- `select_related`：SQL JOIN，适用于 `ForeignKey` 和 `OneToOneField`，一次查询
- `prefetch_related`：多次查询 + Python 层合并，适用于 `ManyToManyField` 和反向 `ForeignKey`
- N+1 问题：循环中访问外键属性导致额外查询

**本系统示例**：
```python
# views.py 中查询发布单时
tasks = ReleaseTask.objects.select_related(
    'release', 'release__application', 'release__environment'
).get(id=task_id)
```

### 1.5 权限与安全基础

#### Q16: RBAC（基于角色的访问控制）是什么？和 ABAC 有什么区别？

**面试官视角**：考察候选人对权限模型的基本理解。

**候选人关注点**：
- RBAC：用户 → 角色 → 权限，简单直观，适合大部分场景
- ABAC：基于属性（用户、资源、环境、时间）动态决策，更灵活但复杂
- 本系统：采用"组织树 + 个人例外"的混合模型，本质上是 RBAC 的变体

**本系统权限模型**：
```
用户 → 组织组（归属/协作） → 角色 → 数据权限规则
                ↓
        个人例外权限（UserPermission）
```

**扩展追问**：RBAC 的角色继承怎么实现？什么是"最小权限原则"？

#### Q17: JWT（JSON Web Token）的结构是什么？有什么优缺点？

**面试官视角**：考察候选人对认证机制的理解。

**候选人关注点**：
- 结构：Header（算法） + Payload（声明） + Signature（签名）
- 优点：无状态、可扩展、跨域支持
- 缺点：无法主动失效、Payload 不加密（需 HTTPS）、Token 体积大
- 存储：`localStorage`（XSS 风险）vs `httpOnly Cookie`（CSRF 风险）

**扩展追问**：如何实现 JWT 的主动失效？Blacklist 方案和 Token 版本号方案的区别？

#### Q18: 什么是 CSRF 攻击？如何防御？

**面试官视角**：考察候选人对 Web 安全的基础知识。

- 防御：CSRF Token、SameSite Cookie、检查 Origin/Referer
- 前后端分离：JWT 存 localStorage 不受 CSRF 影响，但有 XSS 风险

### 4.2 多集群发布设计

#### Q52: 假设你的应用部署在多个 K8s 集群（多云、多地域），如何设计发布流程？

   - 串行发布：一个集群发布完成后再发布下一个
   - 并行发布：同时发布多个集群
   - 分批发布：按批次发布，每批完成后确认
   - 优先级发布：先发布非核心集群，再发布核心集群

   - 局部故障：跳过故障集群，继续发布其他集群

### 4.9 成本优化

#### Q59: 假设你的发布系统每月云成本很高，你会如何优化成本？

**面试官视角**：考察候选人的成本意识和优化能力。

**设计要点**：
1. **资源优化**：
   - 实例规格：根据实际负载选择合适规格
   - 自动伸缩：根据负载自动调整实例数
   - 预留实例：长期使用预留实例，降低单位成本
   - 竞价实例：非核心任务使用竞价实例

2. **架构优化**：
   - 无服务器：适合事件驱动的场景
   - 容器化：提高资源利用率
   - 微服务：按需扩展，避免整体扩容
   - 缓存：减少数据库访问，降低数据库成本

3. **存储优化**：
   - 冷热分离：历史数据归档到低成本存储
   - 数据压缩：压缩日志、备份数据
   - 数据清理：定期清理过期数据
   - 存储分层：根据访问频率选择存储类型

4. **网络优化**：
   - CDN：静态资源使用 CDN
   - 内网通信：服务间使用内网通信
   - 数据压缩：传输数据压缩
   - 连接复用：减少连接建立开销

5. **监控与告警**：
   - 成本监控：监控云资源使用情况
   - 成本告警：成本超过阈值时告警
   - 成本分析：分析成本构成，找出优化点
   - 成本预算：设置成本预算，控制支出

**追问**：
1. 如何监控云成本？
2. 如何评估优化效果？
3. 如何平衡成本和性能？

## 🎯 面试官使用建议

1. **基础题**：快速筛选，每题 2-3 分钟，答不上来的标记
2. **进阶题**：深挖 2-3 个方向，每个方向 3-5 个追问
3. **刁难题**：观察候选人的反应，是否紧张、是否回避细节
4. **场景题**：给候选人思考时间，观察思维过程而非答案

### 评分标准

- **5 分**：回答全面、深入，有实际经验，能举一反三
- **4 分**：回答正确、有一定深度，能回答追问
- **3 分**：回答基本正确，但深度不足，追问困难
- **2 分**：回答有明显错误，或无法回答追问
- **1 分**：完全不会，或明显撒谎

### 红线指标（一票否决）

- 明显撒谎（前后矛盾、细节对不上）
- 基础题大面积不会（超过 50%）
- 态度问题（傲慢、不尊重、拒绝回答）
- 安全意识极差（明文密码、无权限控制）
