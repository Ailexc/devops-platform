OIDC 客户端接入是什么

OIDC 客户端（Relying Party，RP）是接入统一认证的标准协议级方式。应用注册为客户端后，通过 OIDC 授权码 + PKCE 流程让用户登录，拿到 id_token / access_token。门户自身（通过 BFF）和 oidc-demo 都是 OIDC 客户端。

第一步：注册应用

在门户的「应用管理」中注册应用，关键配置：

  • 接入方式：选择 OIDC 客户端（token_mode = OIDC）；
  • 回调地址 redirect_uri：授权码回跳的地址，必须精确登记；
  • 系统自动发放 client_id 与 client_secret（secret 仅展示一次，务必保存）。
redirect_uri 是安全关键：认证中心按精确白名单匹配回调地址（前缀匹配已被禁止）。若回调地址可被篡改，攻击者可把授权码导向自己。登记时必须与实际回调完全一致。

第二步：授权码 + PKCE 流程

  1. 前端跳 /oauth/authorize，携带：response_type=code、client_id、redirect_uri、scope=openid profile、state（防 CSRF）、nonce（防重放）、code_challenge + code_challenge_method=S256（PKCE）；
  2. 认证中心要求用户登录，确认后 302 回回调地址，携带一次性 code 与原样 state；
  3. 应用后端校验 state，用 code + code_verifier + client_secret 调 /oauth/token 换取 token；
  4. 校验 id_token 的 nonce 与签名，用 access_token 调 /userinfo 获取用户信息。
# 应用后端换 token（示意，oidc-demo 的完整实现）
POST /oauth/token
  grant_type=authorization_code
  &code=<授权码>
  &redirect_uri=<回调地址>
  &client_id=<client_id>
  &client_secret=<client_secret>
  &code_verifier=<PKCE 验证值>

第三步：验证令牌

  • id_token：JWT，用 /.well-known/jwks.json 公钥验签名，校验 iss / aud / nonce / exp；
  • access_token：调 /userinfo 或业务 API 用，短时效；
  • refresh_token：后端持有，到期后用于无感续期（会轮换）。

参考实现：oidc-demo

项目自带标准 OIDC 客户端演示（端口 8005），完整展示六步流程：

  1. 生成 PKCE code_verifier + state + nonce，跳认证中心 /authorize；
  2. 认证中心 302 带回一次性 code + state；
  3. 校验 state（防 CSRF）；
  4. 后端用 code + code_verifier + client_secret 换 token；
  5. 解码 id_token 并校验 nonce（防重放）；
  6. 用 Bearer access_token 调 /userinfo。

启动后访问 http://localhost:8005，点"通过统一认证登录"即可走完整流程。

常见错误排查

错误原因
invalid_redirect_uri回调地址与登记白名单不完全一致（含协议/端口/路径）
invalid_grant授权码已过期（5 分钟）或已被使用（一次性）
invalid_clientclient_id / client_secret 错误
id_token nonce 校验失败未携带 nonce 或与应用生成的不一致
state 不匹配回调 state 与发起时不一致（可能被篡改或流程中断）

小结

  • OIDC 客户端接入 = 注册应用（redirect_uri 白名单）→ 授权码 + PKCE → 换 token → 验 id_token。
  • client_secret 只在后端，token 不进浏览器。
  • oidc-demo 提供可直接跑通的参考实现。
