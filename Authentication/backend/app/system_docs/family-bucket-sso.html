要回答的核心问题

认证中心（OIDC Provider）造好之后，全家桶真实系统到底怎么接进来？本项目把六大业务系统全部接入了统一认证，并按三类真实场景分配了三种接入方式——这是"统一认证落地"的实战总览。

三种接入方式全景

方式谁验签业务鉴权代码适合场景本项目系统
① 经网关 forwardAuth网关转认证中心零（读注入头）网关可覆盖的内部应用云管 / 工单 / 权限中心
② 直连 JWKS业务后端本地拉公钥实现一次验签中间件跨网络 / 网关覆盖不到任务管理 / 事件管理
③ 标准 OIDC 客户端协议级（授权码 + PKCE）标准客户端库外部第三方系统发布系统

三种方式共用同一种"统一 JWT"（认证中心 RS256 签发），区别在于验签发生在哪、以及业务系统写多少代码。详见《经网关 vs 不经网关接入》《直连接入与 JWKS 验签》。

身份统一：LDAP

  • 12 个全家桶用户灌入 OpenLDAP，密码统一 demo1234；
  • 用户隶属组织（研发部 / 运维部…），不隶属某个系统；
  • 认证中心启用 LDAP 认证源（AUTH_PROVIDER_ORDER=ldap,local）；
  • 登录页：选择系统 → 选择用户（按组织分组）→ 固定密码；
  • 管理界面：LDAP Account Manager（LAM）可视化运维。

前端闭环

接入不只是"后端 API 验签通过"，还要前端真正串起来：每个系统前端都要消费统一令牌并展示当前用户。统一模式：

门户带 ?token= 跳转→读令牌存本地→立即清理 URL→请求带 Bearer→拉当前用户→界面展示
系统框架令牌 key用户显示
云管Vue 3access_token顶部导航（含中文显示名）
工单Vue 3token侧边栏
权限中心Vue 3iam_token布局顶部
任务管理Vue 3cmdb.token顶栏
事件管理Reactevent.token侧边栏底部
认证 / 授权分离：登录后全局可进所有系统；某系统没权限则空白，走权限中心申请即可——这是设计如此，不是 bug。

网关踩坑（实战价值最高）

内部系统前端纳入统一网关后，两个路由坑必须处理：

现象根因修复
新域名 /api/ 被后端拒mock-app 是无 Host 的 PathPrefix(/api/) 兜底路由，抢占业务域名请求mock-app 路由限定 Host(mock.authentication.orb.local)
加 Host 后仍绕过 forwardAuthAPI 路由与前端 home 路由 priority 相同，/api/ 被 home（前端 nginx 同源反代）抢占，直连后端绕网关业务 API 路由 priority 提到 100

这两个坑只有新域名会踩（老域名因不匹配 home 的 Host 反而"侥幸正常"），任何环境都可能出现，是网关路由配置的通用问题。

小结

  • 统一认证不是"一个接口接所有"，而是按系统场景选方式：网关 / JWKS / OIDC；
  • 身份统一到 LDAP，用户隶属组织而非系统；
  • 前端闭环（令牌消费 + 用户展示）才是"串起来"的完成标准；
  • 三种方式、五系统闭环、网关踩坑与修复——都是面试可展开的实战素材。
