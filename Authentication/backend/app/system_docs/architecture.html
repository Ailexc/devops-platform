分层架构

系统按职责分为四层，每层只做一件事，边界清晰：

  1. 接入层：统一门户（SPA + BFF）负责用户入口与 OIDC 登录；统一网关（Traefik forwardAuth）负责业务 API 的统一 JWT 验签与身份注入。
  2. 认证层：认证中心（FastAPI）是标准 OIDC Provider，提供授权端点、令牌端点、用户信息端点、JWKS 公钥发布，并维护应用注册表。
  3. 数据层：外部共享 PostgreSQL，存用户、应用注册、授权码、刷新令牌与认证日志。
  4. 身份源层：可插拔用户来源（Local 默认 / LDAP / Okta），策略模式、可降级。

技术栈与分工

层技术理由
前端React 19 + Ant Design组件生态成熟，后台系统高效
认证后端Python FastAPI异步高性能，自动 OpenAPI
认证协议OAuth 2.1 + PKCE + OIDC企业级标准，非自研私有协议
令牌RS256 + JWKS非对称，公钥可分发给异构系统
网关Traefik forwardAuth配置即接入，验证逻辑可扩展
数据PostgreSQL（外部共享库）数据安全、贴近生产
部署Docker Compose + OrbStack一键全栈，域名自动解析

小结

  • 四层架构：接入 / 认证 / 数据 / 身份源，职责解耦。
  • 门户 = SPA + BFF，认证中心 = OIDC Provider，网关负责统一 JWT 验签。
  • 标准协议 + 外部共享库 + 容器化，符合企业级定位。
