# 统一认证中心 — 云端部署迁移指南（OrbStack → 阿里云 Docker）

> 本文回答一个核心问题：本地靠 OrbStack 自动生成 `*.authentication.orb.local` 域名，上云后没有自动域名，**应用间跳转链接怎么配？**
> 结论先行：**一套架构原样搬到云上，只需把"浏览器可达地址"从 `.orb.local` / `localhost` 换成真实域名，容器间调用继续用 compose 服务名，一行业务代码都不用改。**

---

## 一、背景与目标

| 项 | 本地（现状） | 云上（目标） |
|---|---|---|
| 部署环境 | OrbStack（Mac 本地） | 阿里云 ECS 一台（Docker） |
| 域名来源 | OrbStack 内置 DNS 通配符 `*.authentication.orb.local` | 自有域名泛解析 `*.example.com` → 服务器公网 IP |
| 应用间跳转 | `localhost:8xxx` / `.orb.local` | `https://xxx.example.com` |
| 容器间调用 | compose 服务名（`auth-backend:8000`） | compose 服务名（不变） |
| 对外入口 | Traefik 统一网关 | Traefik 统一网关（+ HTTPS 证书） |

---

## 二、核心概念澄清（先把容易混的地方掰正）

### 2.1 两种"跳转"，要求完全相反

| | ① 浏览器跳转（redirect） | ② 服务间调用（server-to-server） |
|---|---|---|
| 谁发起 | 浏览器（用户电脑/手机） | 后端容器（代码里发 HTTP 请求） |
| 例子 | SSO `home_url?token=xxx`、OIDC `redirect_uri`、门户点开应用 | forwardAuth 验签、direct-app 拉 JWKS、oidc-demo 换 token |
| 地址要求 | **必须是公网可达地址**（真实域名 / 公网 IP） | **可以用 compose 服务名**（`auth-backend:8000`） |
| 为什么 | 浏览器在服务器之外、不在 Docker 网络内，解析不到容器内网 | 容器在同一 compose 网络，Docker 内置 DNS 认识服务名 |

**一句话：只要跳转链路经过浏览器，一端就必须是公网可达地址；只有后端容器之间才认识服务名/容器 IP。**

### 2.2 Docker 没有"命名空间"

- Docker 用于"应用分组互通"的概念是 **network（网络）**：`docker compose up` 默认把所有服务放进同一网络，网络内用**服务名**互相访问。
- **namespace 是 Kubernetes 的概念**（资源隔离/分组），不是 Docker 提供跳转域名的机制；Linux 内核 namespace 是容器隔离的底层实现，与"应用间跳转"无关。
- 用户口中的"同一命名空间"在 Docker 世界里 = **所有容器在同一个 compose 网络里**，这一点本地与云端完全一致。

### 2.3 为什么云上"没有自动域名"

`.orb.local` 是 OrbStack 帮你做的：你写 label `dev.orbstack.domains=...`，它就注册通配符 DNS 并转发到对应容器端口。**Docker 本身只提供容器内服务名 DNS，不提供公网域名。** 公网域名属于 DNS 服务商（阿里云 DNS / Cloudflare）的职责。所以云上的工作 = 自己补上"域名 → 服务器 → 容器"这一段 = **反向代理**，而你项目里已经有 Traefik。

## 三、目标架构（方案 A：一台云主机 + 泛解析 + Traefik）

```
用户浏览器（公网）
      │ 仅能访问公网域名
      ▼
 *.example.com 泛解析（DNS 服务商）
      │  A 记录 → 服务器公网 IP
      ▼
┌──────────────────────────────────────────────┐
│  阿里云 ECS（一台）                            │
│                                              │
│  Traefik 统一网关（:80 / :443，Let's Encrypt） │
│   portal.example.com   → portal 容器          │
│   mock.example.com     → mock-app 容器        │
│   direct.example.com   → direct-app 容器      │
│   auth.example.com     → auth-backend 容器    │
│   …                                          │
│                                              │
│  ┌─────── Docker compose 同一网络 ─────────┐  │
│  │ 容器之间用服务名互调：                    │  │
│  │  forwardAuth → http://auth-backend:8000 │  │
│  │  JWKS        → http://auth-backend:8000 │  │
│  │  LDAP        → ldap://openldap:389      │  │
│  └─────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

**架构原则：浏览器只和"网关域名"打交道，容器之间永远走服务名。** 这两个地址域分开管理，上不上云、换不换服务器都不影响业务逻辑。

---

## 四、跳转地址写法可行性对照表

| 跳转类型 | 容器 IP（172.x.x.x） | compose 服务名 | 公网域名 |
|---|---|---|---|
| 后端 → 后端 | 能，但不推荐（IP 重启会变） | ✅ 推荐 | 没必要 |
| 浏览器 → 应用 | ❌ 浏览器够不着内网 | ❌ 浏览器解析不到 | ✅ 必须 |

> 即使部署在**同一台机器、同一网络**，浏览器跳转也**不能**走容器 IP/服务名——用户的浏览器在服务器外面，够不着 Docker 内网。

## 五、本项目迁移清单

### 5.1 不用改（服务间调用，走服务名，云上原样）

| 位置 | 内容 |
|---|---|
| `gateway/dynamic/dynamic.yml` | `forwardAuth` → `http://auth-backend:8000/api/auth/verify` |
| `direct-app` 环境变量 | `AUTH_JWKS_URL=http://auth-backend:8000/.well-known/jwks.json` |
| `oidc-demo` | `AUTH_TOKEN_URL` / `AUTH_USERINFO_URL`（`auth-backend:8000`） |
| `backend/app/config.py` | `ldap_server_uri=ldap://openldap:389` |

### 5.2 必须改（浏览器可达地址，从 `.orb.local`/`localhost` → 真实域名）

| 位置 | 现在 | 云上改成 |
|---|---|---|
| 数据库 `app_registration.home_url`（`backend/app/seed.py` 硬编码 `localhost:8xxx`） | `http://localhost:8001` … | `https://mock.example.com` … |
| `oidc-demo` `REDIRECT_URI` | `http://localhost:8005/callback` | `https://oidc.example.com/callback` |
| `oidc-demo` `AUTH_AUTHORIZE_URL` | `http://localhost:8002/oauth/authorize` | `https://auth.example.com/oauth/authorize` |
| `backend/app/config.py` `portal_url` / `mock_app_url` / `issuer` | `localhost` / `auth.devops.orb.local` | 真实域名 |
| 前端 `frontend/src/data/e2eScenes.ts` / `presentationScenes.ts` 写死地址 | `localhost:8005` 等 | 真实域名 |
| Traefik 入口 | `:8001 / :8004` 端口映射 | 网关只暴露 `80/443`，按域名路由 |

### 5.3 工程实践：把这些"浏览器可达地址"全部环境变量化

- `config.py` 已是此思路（`portal_url`、`mock_app_url`、`issuer` 走 Settings）。
- 建议继续抽成环境变量：`PORTAL_URL`、`APP_PUBLIC_BASE_URL`、`REDIRECT_URI`、`JWT_ISSUER`。
- 本地 `.env` 填 `.orb.local` / `localhost`，云上 `.env` 填真实域名，**一键切换、代码零改动**。
- `seed.py` 的 `home_url` 建议改为"环境变量模板 + 数据库可改"，避免硬编码。

## 六、具体配置示例（阿里云）

### 6.1 DNS 泛解析

在 DNS 服务商控制台新增两条解析：

| 主机记录 | 类型 | 记录值 |
|---|---|---|
| `@` | A | 服务器公网 IP |
| `*` | A | 服务器公网 IP |

> 泛解析一次配好，以后新增子应用（`new.example.com`）无需再配 DNS，只需在 Traefik 加一条路由。

### 6.2 安全组

阿里云安全组放行：
- `80`（HTTP，供 Let's Encrypt 验证 + 跳转 HTTPS）
- `443`（HTTPS）
- `22`（SSH，可限制来源 IP）
- 其余容器端口（8001~8005 等）**不要**对外放行，统一走网关。

### 6.3 compose 端口收敛

所有业务容器去掉对外 `ports` 映射（或仅保留内部服务名访问），只留 Traefik 暴露 80/443：

```yaml
# 示例：mock-app / direct-app / oidc-demo 不再对外映射端口
services:
  mock-app:
    build: ./mock-app
    # ports: 去掉 —— 只能经 Traefik 访问
  traefik:
    image: traefik:v3.2
    ports:
      - "80:80"      # HTTP（Let's Encrypt 用）
      - "443:443"    # HTTPS
      - "8080:8080"  # Traefik Dashboard（可选，安全组限内网）
```

> 容器间互调走 compose 服务名，**不需要**端口映射。删掉映射后内网互调依然正常，且更安全。

### 6.4 Traefik：子域名路由 + 自动 HTTPS（Let's Encrypt）

```yaml
# gateway/dynamic/dynamic.yml（云端版节选）
entryPoints:
  web:
    address: ":80"
    http:
      redirections:
        entryPoint:
          to: websecure
          scheme: https
  websecure:
    address: ":443"

certificatesResolvers:
  letsencrypt:
    acme:
      email: you@example.com
      storage: /letsencrypt/acme.json
      httpChallenge:
        entryPoint: web

routers:
  portal:
    rule: "Host(`portal.example.com`)"
    entryPoints: ["websecure"]
    tls:
      certResolver: letsencrypt
    service: portal-service
  mock-app:
    rule: "Host(`mock.example.com`) && PathPrefix(`/api/`)"
    entryPoints: ["websecure"]
    tls:
      certResolver: letsencrypt
    middlewares: [auth-forward]
    service: mock-app-service
  # …其余应用同理
```

> 用子域名方案，`*.example.com` 泛解析 + 一个证书覆盖所有子域，与你本地 `.orb.local` 的体验完全一致。

### 6.5 两台机器怎么办（扩展）

- 方案 A 是"一台机全装"。若拆多机：业务应用与认证中心分机部署时，**服务间调用从 compose 服务名改为"内网域名/IP + 应用层鉴权"**，浏览器跳转仍是公网域名不变。
- 更进一步就是 k8s（Service 名 = compose 服务名对应物，Ingress = Traefik 对应物），或云托管平台自动域名。对当前 Demo 规模，一台机足够。

## 七、分步实施清单（照着做即可）

1. **买域名 + DNS 泛解析**：`@` 和 `*` 都解析到服务器公网 IP。
2. **云主机装 Docker**：`apt install docker.io docker-compose-plugin`（或官方脚本）。
3. **安全组放行** 80/443/22，其余端口不外露。
4. **拉代码到服务器**，复制 `.env.production`（填真实域名）为 `.env`。
5. **改 compose**：业务容器去掉对外 `ports`，Traefik 暴露 80/443。
6. **改 Traefik**：按 6.4 加子域名路由 + Let's Encrypt。
7. **改浏览器可达地址**：按 5.2 清单把 `home_url` / `redirect_uri` / `portal_url` / `issuer` 等换成真实域名。
8. **`docker compose up -d --build`** 启动，验证。

## 九、面试可讲的点

1. **两种地址域**：浏览器跳转走公网域名，容器互调走服务名——讲清楚为什么，体现对 Docker 网络的理解。
2. **配置收敛**：所有浏览器可达地址环境变量化，本地/云端一键切换，代码零改动。
3. **统一入口安全**：业务容器不对外暴露端口，全部收口到 Traefik，配合 forwardAuth 统一鉴权，减少攻击面。
4. **演进路径**：单机 Docker → 多机拆分（服务名变内网域名）→ k8s（Service/Ingress 是同一套心智模型的规模化），体现架构演进思维。
