
## 二、分层职责

| 层 | 组件 | 职责 |
|----|------|------|
| 接入层 | Traefik 网关 | 统一入口、路由、forwardAuth 统一鉴权（校验 JWT，放行/拒绝） |
| 门户层 | Portal（React19+antd） | 登录、应用广场、个人中心，承担「统一门户」作用 |
| 认证层 | Authentication Service | 登录/登出/SSO、签发统一 JWT、JWKS 公钥发布、身份源抽象与降级 |
| 应用层 | 应用注册表 | 维护各业务系统元数据（id、名称、图标、homeUrl、secret、SSO 类型） |
| 数据层 | SQLite（Demo） | 用户、应用注册、审计日志 |
| 身份源层 | Local / LDAP / Okta | 用户身份的真实校验来源（可插拔） |

## 三、关键技术决策

### 1. 统一凭证：RS256 签名 JWT
- 认证中心用 **RSA 私钥**签名 JWT（RS256），公钥通过 `/.well-known/jwks.json` 发布
- 各业务系统（异构：Go/Python/Node）用标准 **jose/jwks 客户端**本地验签，无需回源认证中心
- 面试点：对称（HS256）vs 非对称（RS256）签名、JWKS、密钥轮换

### 2. 身份源抽象 + 降级链（核心亮点）
- `Authenticator` 抽象接口：`authenticate(username, password) -> UserProfile`
- 多实现：`LocalAuthenticator` / `LdapAuthenticator` / `OktaAuthenticator`
- `AuthProviderChain`：按配置顺序尝试，**失败自动降级**到下一个身份源
- 详见 `docs/04-身份源与认证降级.md`

### 3. 统一网关 forwardAuth
- 参照 `PermissionCenter` 的 Traefik 做法
- Traefik `forwardAuth` 中间件将请求转发到认证中心 `/api/auth/verify`
  - 返回 `200`：放行，并在请求头注入 `X-Auth-User` 等身份信息
  - 返回 `401/403`：拦截，302 到门户登录页
- 演示 `mock-app` 作为「被统一网关保护的业务应用」

### 4. SSO 单点登录流程
- 门户登录成功后，会话与 JWT 建立
- 用户点击应用 → 携带 JWT 跳转业务系统 → 业务系统（或网关）验证 JWT → 无感进入
- Demo 简化实现 + 文档说明真实 OIDC 授权码流程（见 `docs/03`）

## 四、技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| 后端 | Python 3.11+ / FastAPI | 异步、自动 OpenAPI 文档，开发效率高 |
| ORM | SQLAlchemy 2.0 | 声明式模型 |
| 数据库 | SQLite（Demo） | 零依赖；预留 PostgreSQL 切换 |
| 密码 | bcrypt（passlib） | 密码哈希 |
| JWT | PyJWT / cryptography | RS256 签名 + JWKS |
| LDAP | ldap3 | LDAP bind 认证 |
| 前端 | React 19 + Ant Design 6 | 统一门户 |
| 网关 | Traefik（forwardAuth） | 统一鉴权演示 |
| 编排 | Docker Compose（OrbStack） | 一键全栈启动 |
