# 统一认证中心 — 5 分钟面试演示脚本

> 定位：拿着这份脚本，就能在 5 分钟内把「统一门户 + SSO + 认证中心」完整演示并讲清楚。
> 配合 `docs/06-面试准备.md`（问答）与 `docs/07-开发计划.md`（演进）使用。
> 每幕 = 目标 / 操作 / 讲解词 / 预期画面 / 面试要点。

---

## 演示前检查单（务必先过一遍）

```bash
# 1. 确认全栈服务都在运行
docker compose ps   # auth-backend / portal / gateway / mock-app / direct-app / pilot-app / oidc-demo 均为 Up

# 2. 确认端口可用
#    门户 5175 / 认证 API 8002 / 网关 8001 / 直连 8003 / 试点 8004 / OIDC 8005 / Traefik 面板 8080

# 3. 演示账号
#    admin / admin1234（管理员，可进应用管理）
#    zhangsan / demo1234（普通用户）
```

> 若容器没起：`cd Authentication && docker compose up -d --build`

## 第 0 幕 · 开场（30 秒）—— 先讲背景，不讲技术

**目标**：让面试官知道"为什么有这个项目"。

**讲解词**：
> "我基于真实工作经验复刻了一套企业级统一认证体系。真实场景是：用户通过 EAA 平台进入统一门户，门户背后的认证服务以 Okta 为身份源校验用户，并支持降级到 LDAP；认证通过后签发**跨系统共用的 JWT**，用户即可无感访问门户里所有已授权应用。这个 Demo 把它完整还原成了'统一门户 + 认证中心 + SSO'，并且**支持多种业务系统接入方式**。"

**预期画面**：门户登录页（先别登录）。

---

## 第 1 幕 · 统一门户 + 登录认证（1 分钟）★必演

**目标**：一次登录，拿统一凭证，进入数据驱动的应用广场。

**操作**：
1. 打开 `http://portal.authentication.orb.local`
2. 用 `admin / admin1234` 登录
3. 停留应用广场，让面试官看到 10 个应用卡片

**讲解词**：
> "这是统一门户。用户在门户登录一次，认证中心校验后签发一张**统一 JWT**（RS256 签名，公钥通过 `/.well-known/jwks.json` 发布）。登录后看到的是**应用广场**——它不是写死的，是由**应用注册表**数据驱动的：注册一个应用，广场立即出现。每个卡片右上角标注了它的**接入方式**（网关接入 / 直连接入）。"

**预期画面**：欢迎横幅"系统管理员"，广场卡片 10 个，卡片带接入方式角标。

**面试要点**：数据驱动 vs 写死；RS256 与 JWKS 的意义（见 docs/06 Q2/Q3）。

---

## 第 2 幕 · 身份源抽象 + 降级链（1 分钟）

**目标**：展示本项目最核心的设计——「Demo 没有 Okta/LDAP 怎么办」。

**操作**：
1. 打开 `http://localhost:8002/api/system/health`（或 Swagger）
2. 展示降级链：`local` 可用，`ldap`/`okta` 预留
3. （可选，时间够时）演示 LDAP：`.env` 开 `AUTH_PROVIDER_ORDER=ldap,local` → `docker compose --profile ldap up -d` → 用 `zhangsan/demo1234` 登录，个人中心显示"认证来源：LDAP"

**讲解词**：
> "真实项目里用户可能来自 Okta 或 LDAP。我把'身份源'抽象成统一接口（`Authenticator`），支持 **Local / LDAP / Okta 三种实现**，并组成**降级链**：身份源不可用自动降级到下一个。这里有个关键设计——**认证失败不降级，只有身份源不可用才降级**，防止攻击者穿透到弱身份源。Demo 默认用本地用户库（零依赖），需要时打开 LDAP 容器即可。"

**预期画面**：health 返回 `local: available`，ldap/okta 标记不可用（未启用）。

**面试要点**：策略模式、failover 高可用、安全边界（docs/06 Q4）、LDAP bind 原理（Q6）。

---

## 第 3 幕 · 三种接入方式（1.5 分钟）★必演

**目标**：回答面试官最关心的"业务系统怎么接入"。

### 3.1 网关模式（forwardAuth）
**操作**：点广场「工单中心 PilotApp」→ 无感进入工作台。
**讲解词**：
> "第一种接入方式：**经统一网关**。请求先进网关，网关用 forwardAuth 把 JWT 转发给认证中心 `/api/auth/verify` 校验，通过后注入 `X-Auth-*` 头再放行。业务后端**零鉴权代码**，直接读请求头就知道是谁——看，这里显示'当前用户：张三'，还生成了他的工单数据。"

**预期画面**：工作台显示当前用户 + 待办/工单列表。

### 3.2 直连模式（JWKS 自验签）
**操作**：展示 `direct-app`（可先 curl 或直接说明）。
**讲解词**：
> "第二种：**不经网关的应用**（外部部署/内部服务）。因为 JWT 是 RS256 非对称签名，应用拉取认证中心发布的公钥（JWKS），在**本地验签**，不用每次回源。`direct-app` 里就有这么个 20 行的验签中间件。"

**预期画面**：带统一 JWT 直连 `localhost:8003/api/me` 返回用户；无 token 401。

### 3.3 OIDC 授权码模式
**操作**：打开 `http://localhost:8005` → 点「通过统一认证登录」→ 走完整授权码流 → 显示"我的信息"。
**讲解词**：
> "第三种：**OIDC 授权码模式**（企业标准）。看这个完整流程：前端跳认证中心 `/authorize`（带 `client_id`）→ 认证中心校验统一 JWT 后发一个**一次性授权码 code** → 应用**后端**用 `code + client_secret` 换真正的 token → 再调 `/userinfo` 拿用户信息。注意：**token 不经过浏览器 URL，client_secret 只存在应用后端**——这就是它比直接传 token 安全的原因。"

**预期画面**：OIDC 演示应用页面，4 步流程全部 ✅，显示"张三/研发部"。

**面试要点**：forwardAuth 注入 X-Auth-*（docs/03）；JWKS 本地验签（Q2/Q3）；OIDC 两阶段、client 凭证（Q8）。

## 第 4 幕 · 应用生命周期管理（1 分钟，可跳过）

**目标**：展示"接入一个新应用"是可视化操作。

**操作**：
1. 顶栏用户下拉 → 「应用管理」
2. 点「接入新应用」→ 向导：填基本信息 → 注册
3. 展示自动发放的 `client_id / client_secret`（含保密提示）
4. 接入配置说明 → 完成
5. 回应用广场，新应用已出现

**讲解词**：
> "接入应用不用改代码：在开发者控制台填个表单，系统自动发放应用凭证（client_id/client_secret），给出接入配置说明，应用立即上架到广场。这对应真实企业里的**应用注册/开发者控制台**。"

**预期画面**：向导 4 步走完，广场多一个应用。

**面试要点**：应用凭证模型、client_secret 一次性展示与保密、数据驱动。

---

## 第 5 幕 · 收尾串讲（30 秒）

**讲解词**：
> "总结一下：**统一凭证**是 RS256 JWT（公钥 JWKS 发布）；**验证方式**有两条路——网关统一验票、或应用本地验签；**标准协议**是 OIDC 授权码（client 凭证换 token）；**身份源**支持 Okta/LDAP/Local 并可降级。整个链路：登录一次 → 统一 JWT → 三种方式接入的所有应用无感访问。"

**预期画面**：任意页面收尾即可。

**面试要点**：一句把"认证、授权、接入"串成完整叙事，引导追问。
