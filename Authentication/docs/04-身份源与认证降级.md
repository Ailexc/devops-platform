# 统一认证中心 — 身份源与认证降级（核心设计）

> 本文档是「Demo 环境没有 Okta / LDAP 怎么办」的完整答案，也是本项目最核心的面试亮点。

## 一、问题

真实项目以 **Okta** 为身份源验证用户，**降级到 LDAP**。但 Demo 环境既没有 Okta 也没有 LDAP，如何既还原真实场景、又能在本地跑起来？

## 二、答案：身份源抽象层 + 降级链（failover）

把「身份源」抽象为统一接口，认证中心不关心用户来自哪个身份源，只依赖接口：

```
Authenticator（抽象）
├── authenticate(username, password) -> UserProfile   # 校验，失败抛异常
├── is_available() -> bool                            # 探活，用于降级判断
└── name / order                                      # 身份源名称与优先级

UserProfile（标准化返回，屏蔽不同身份源的差异）
├── uid        # 统一用户标识
├── username   # 登录名
├── display_name
├── email
├── department
├── source     # local / ldap / okta（记录实际校验来源，可审计）
└── groups/roles
```

### 三种实现

| 实现 | 校验方式 | Demo 依赖 | 用途 |
|------|----------|-----------|------|
| `LocalAuthenticator` | 查本地 `users` 表 + bcrypt 校验 | 无 | **默认**，先跑通 SSO 主链路 |
| `LdapAuthenticator` | 连接 OpenLDAP，DN 定位 + bind 校验 | OpenLDAP 容器 | 还原真实 LDAP 认证 |
| `OktaAuthenticator` | OIDC 授权码流 | （预留） | 还原 Okta 场景 |

### 降级链（AuthProviderChain）

```python
class AuthProviderChain:
    providers = [OktaAuthenticator, LdapAuthenticator, LocalAuthenticator]  # 按配置顺序

    def authenticate(username, password):
        for provider in providers:
            if not provider.is_available():
                log(f"{provider.name} 不可用，跳过")
                continue
            try:
                return provider.authenticate(username, password)
            except AuthProviderUnavailable:
                log(f"{provider.name} 异常，降级到下一个身份源")
                continue
        raise AuthenticationFailed("所有身份源均不可用")
```

- 配置 `AUTH_PROVIDER_ORDER=okta,ldap,local` 控制优先级
- **降级语义**：
  - `AuthenticationFailed`（用户不存在/密码错）→ **不降级**，直接返回失败（避免降级导致安全绕过）
  - `AuthProviderUnavailable`（网络/超时/服务不可用）→ **降级**到下一个身份源
- 面试点：区分「认证失败」与「认证源不可用」，前者不降级、后者才降级——**安全边界**

### 配置示例（`.env`）

```env
# 身份源顺序与开关
AUTH_PROVIDER_ORDER=ldap,local
AUTH_PROVIDER_LDAP_ENABLED=true
AUTH_PROVIDER_LOCAL_ENABLED=true

# LDAP 连接
LDAP_SERVER_URI=ldap://openldap:389
LDAP_BIND_DN=cn=admin,dc=devops,dc=com
LDAP_BIND_PASSWORD=adminpass
LDAP_USER_SEARCH_BASE=ou=people,dc=devops,dc=com
LDAP_USER_SEARCH_FILTER=(uid={username})
```

## 三、为什么这样设计（面试口径）

1. **策略模式**：新增身份源（如接真实 Okta / AD）只加一个实现类，开闭原则
2. **降级即高可用**：生产环境身份源故障自动切换，保证登录不中断
3. **安全边界**：认证失败不降级，防止恶意尝试穿透到弱身份源
4. **可审计**：`UserProfile.source` 记录用户实际由哪个身份源认证，满足审计
5. **渐进式**：Demo 默认 Local 零依赖跑通，按需打开 LDAP/OIDC 完整演示

## 四、LDAP 认证细节（知识点）

LDAP 认证不是「传密码去比对」，而是两步：

1. **搜索（search）**：用服务账号 bind 后，在 `ou=people,dc=devops,dc=com` 下按 `(uid={username})` 搜索，得到用户的 **DN**（如 `uid=zhangsan,ou=people,dc=devops,dc=com`）
2. **绑定（bind）**：用该 DN + 用户密码再次 bind 到 LDAP——bind 成功即密码正确

```
ldap3 示例（伪代码）：
server = Server(uri)
conn = Connection(server, bind_dn, bind_password)   # 服务账号
conn.search(search_base, f"(uid={username})", attributes=...)
user_dn = conn.entries[0].entry_dn
conn2 = Connection(server, user_dn, password)        # 用户 bind
valid = conn2.bind()
```

## 五、Demo 里 OpenLDAP 怎么起

- `docker-compose.yml` 中 `openldap` 为**可选服务**（compose profile `ldap`），默认全栈不依赖它
- 使用 `osixia/openldap:1.5.0` 镜像（bitnami 镜像在部分镜像源 403）
- 启动时通过 entrypoint 将 `ldap/seed.ldif` 复制进容器 custom 目录，自动导入演示目录树（`dc=devops,dc=com` + `ou=people` 若干用户）
- 认证中心配置 `LDAP_*` 环境变量指向容器名 `openldap`（端口 389）
- 启用方式：`docker compose --profile ldap up -d`，并在 `.env` 开启 `AUTH_PROVIDER_LDAP_ENABLED=true`、调整 `AUTH_PROVIDER_ORDER=ldap,local`
- 已实测：LDAP 用户 `zhangsan/demo1234` 登录成功，`source=ldap`，部门等信息从目录树读取；密码错误返回 401 且**不降级**（安全边界）

## 六、Okta 预留说明

- Demo 不接真实 Okta，`OktaAuthenticator` 作为接口预留
- 可在 `ldap` 之外自建轻量 **mock OIDC Provider**（实现 `/authorize`、`/token`、`/userinfo`、`/.well-known/openid-configuration`），完整还原授权码流（见 `docs/03`）
- 本文档说明 + 接口预留，面试时口述 OIDC 流程即可
