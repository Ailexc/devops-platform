复盘总结

一、项目亮点

  • 真能跑：不是静态 demo——审批、自动办理、规则拦截、详情追踪全部真实落库，一键跑通 4 个流程。
  • 可解释：规则命中逐条给「判定明细 + 数据来源」，自动执行给「入参/出参/日志」，整个系统说得清。
  • 可配置：流程、规则、能力都是配置化，新增一个场景不需要改代码。
  • 口径统一：提单路径预演、详情流程追踪、E2E 测试用同一套路径计算，前后一致。

二、技术难点与解法

难点解法
Beeflow 树形定义引擎无法直接跑归一化为 nodes+edges，并兼容两套审批人格式
规则要可配置又安全结构化 AST + 上下文指标层，解释器求值不用 eval
自动办理要可观察能力作业 + 时间线日志 + 流程追踪逐节点展示
验证整体能力太繁琐HTTP 驱动 E2E：多用户 token 切换，一键跑全流程并落库

三、踩过的坑

  • 审批人解析两套格式不一致 → 兼容 Beeflow assigneeType。
  • 前端构建缓存导致旧产物 → 无缓存重建 + 校验容器产物。
  • 办理节点 auto 模式无待办，E2E 步骤看不到 → 扫描能力作业补录「自动办理」步骤。
  • 条件分支节点全部展示太乱 → 按实际路径展示，跳过分支不出现。

四、改进方向

  • 接入真实能力（CMDB/邮件/飞书审批）替换 Mock。
  • 规则引擎增加更多操作符与聚合指标，支持跨表单校验。
  • 办理节点支持人工回填、多轮动作、重试策略。
  • 性能与监控：接入真实数据库、任务队列、链路追踪。
