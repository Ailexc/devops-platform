# 对外集成设计（10-对外集成设计）

> 本文档固化工单/流程平台的**对外集成全景**，作为功能开发的依据与面试讲解的事实底座。
> 说明：以下内容来自真实业务回忆整理，与 Demo 代码现状存在差距（见文末「现状与差距」）。

---

## 一、总体框架：入站 × 出站 × 基座

企业级工单/流程平台的对外集成，按「方向 × 类型 × 业务语义」划分为三个层次：

```mermaid
graph TB
    subgraph 入站 Inbound（别人进来）
        A1[开放 API<br/>监控告警自动建单 · 程序发起工单]
        A2[协同渠道<br/>飞书卡片办理/查看]
        A3[结果回流<br/>Webhook 回调端点 · 队列订阅]
    end
    subgraph 出站 Outbound（我们出去）
        B1[审计平台<br/>工单全量推送]
        B2[变更中心<br/>变更单推送]
        B3[消息中心<br/>统一出口 · 发飞书/其他 IM]
        B4[任务中心<br/>下发执行任务 · 双工签名]
        B5[发布平台<br/>发起审批 · 回调推进（规划）]
    end
    subgraph 基座（不体现在功能菜单）
        C1[网关 · 统一鉴权]
        C2[权限中心 · 注册应用]
        C3[SSO 身份链 · EAA→Okta→LDAP→JWT]
        C4[凭据中心 · 执行取凭据]
        C5[日志平台 · 插件采集]
    end
    A1 & A2 & A3 -->|推进流程| 工单系统
    工单系统 --> B1 & B2 & B3 & B4 & B5
```

**核心原则：**
1. **消息通道专指"执行结果回流"**——语义单一，不往里塞其他集成。
2. **对外发消息一律走消息中心**，不直接调通讯软件（统一出口、多渠道扩展、限流熔断、审计）。
3. **所有对内对外调用统一走 API 网关**——入站经网关鉴权后进平台，出站经网关统一鉴权/限流/审计后出去。

## 二、集成对象清单

### 分类原则（2026-08 确认）

按**协议形态**分两类，每类双向（用「方向」字段标记双向）：
- **同步 API** → 开放 API：业务方接入（外部调用本系统）+ 能力平台对接（本系统调用外部）
- **异步消息** → 消息通道：对外订阅（接收外部状态）+ 主动推送（上报外部平台）
- 对外回调端点（HTTP POST）属**同步 API**，归开放 API；队列订阅属**异步消息**，归消息通道

### 1. 开放 API（同步 API · 双向）

| 项 | 说明 |
|---|---|
| 业务语义 | **同步 HTTP API 集成**，双向：外部调用本系统 + 本系统调用外部 |
| **业务方接入**（外部调用本系统） | 监控告警自动建单、CI 流水线/程序发起、发布平台（发起审批+回调推进）、对外回调端点（外部任务完成回报结果） |
| **能力平台对接**（本系统调用外部） | 任务中心（下发执行任务，App ID/Secret 签名，双向）、消息平台（统一出口发 IM，单向） |
| 管理面 | **开放 API 页**：业务方接入方登记（App/API Key/调用示例）+ 对外回调端点 + 能力平台对接清单（方向标记） |
| 优先级 | 高（监控告警是最高频接入） |

> 监控告警场景：监控平台探测到故障 → 自动调用开放 API 创建工单 → 分派给负责人处理。真实业务中使用频率最高。

### 2. 协同渠道（入站交互 + 出站通知 · 渠道）

| 项 | 说明 |
|---|---|
| 业务语义 | **交互入口**：用户通过 IM 卡片（飞书等）查看/办理待办 |
| 对接对象 | 飞书（当前）、企业微信/钉钉（可扩展） |
| 交互 | 飞书卡片查看表单、办理节点（审批/填单） |
| 通知 | 审批提醒、结果通知经卡片/消息推送（**走消息中心**，不直连 IM） |
| 管理面 | **协同渠道配置**：IM 应用 AppID/Secret、回调地址、渠道开关（规划） |
| 优先级 | 中（Demo 可先做说明页/占位） |

### 3. 消息通道（异步消息 · 双向）

| 项 | 说明 |
|---|---|
| 业务语义 | **异步消息集成**，双向：对外订阅（接收外部状态）+ 主动推送（上报外部平台） |
| 通道① | **对外订阅**（接收）：队列订阅 `workflow.task.status`，实时获取执行进度（含中间态），区别于回调只能拿最终态 |
| 通道② | **主动推送**（上报）：工单事件推送到审计/变更中心（工单全量、变更单），经网关鉴权与审计 |
| 管理面 | **消息通道页**：消息队列订阅 + 主动推送清单 + 已订阅通道 |
| 优先级 | 高（已实现页面） |

> 说明：外部任务完成的结果回执为 HTTP 回调端点，属**同步 API**，在「开放 API」页管理；本页只承载异步消息。

### 4. 出站对象分布（按形态归入开放 API / 消息通道）

| 对接对象 | 交互方式 | 形态 | 归属页面 |
|---|---|---|---|
| **审计平台** | 工单全量推送（事件驱动） | 异步消息 | 消息通道 · 主动推送 |
| **变更中心** | 变更单推送 | 异步消息 | 消息通道 · 主动推送 |
| **消息平台** | 统一消息出口（发 IM） | 同步 API | 开放 API · 能力平台对接 |
| **任务中心** | 下发执行任务（双工签名） | 同步 API | 开放 API · 能力平台对接（双向） |
| **发布平台** | 发起审批 + 回调推进（规划） | 同步 API | 开放 API · 业务方接入（双向） |

### 5. 基座（不体现在功能菜单）

| 基座 | 说明 |
|---|---|
| **API 网关** | 入站/出站统一鉴权、限流、审计 |
| **权限中心** | 本系统作为应用注册，走网关统一鉴权，无需主动集成 |
| **SSO 身份链** | EAA → Okta → LDAP → JWT，多应用单点，平台不做独立账号体系 |
| **凭据中心** | 自动化执行高危操作前从凭据中心取凭据，平台不落库明文密钥 |
| **日志平台** | 安装采集插件读取日志目录，无需主动推送 |

## 三、身份链路（基座 · 一句话叙事）

```
用户 → EAA（准入） → Okta（IdP） → LDAP（目录） → JWT Token
```

- JWT 在本系统作用域内（几个应用）通用，实现应用间单点登录。
- 面试叙事：*「身份走统一 SSO（EAA→Okta→LDAP→JWT），多应用单点，平台不做独立账号体系。」*

## 四、安全模型：双向签名（重点）

工单系统与任务中心是**双向互信**，出站/入站各一套签名机制，镜像对称：

| 方向 | 动作 | 安全机制 |
|---|---|---|
| **出站**（工单平台 → 任务中心） | 下发任务 | 工单平台注册到任务中心 → 获取 **App ID + App Secret**；调用时把 **参数 + 请求路径 + App 凭证** 做整体签名；任务中心校验"是否注册、是否允许" |
| **入站**（任务中心 → 工单平台） | 回报结果 | 走消息通道回调端点，工单平台用 **HMAC-SHA256 验签**（X-Callback-Signature）验证来源 |

**任务标识模型**：任务不能单独存在，必须挂在某个服务/应用下，因此每个任务注册时都有**任务应用标识（唯一 ID）**；调用时一并传过去，任务中心校验是否已注册、是否允许执行。

> 面试叙事：*「工单系统与任务中心双向互信：下发任务带 App ID/Secret 整体签名（参数+路径+凭证），完成回执我们 HMAC 验签；任务挂服务/应用，有唯一任务标识，对方校验注册与权限。」*

## 五、CMDB 读写模型

| 维度 | 说明 |
|---|---|
| **读**（主） | 表单大部分数据来自 CMDB，主读 |
| **写**（异步） | 提交到任务中心异步执行写操作 |
| **技术亮点** | 自研 **CMDB QuerySet**：底层实现 Django 原生 QuerySet 全部能力，用 Django ORM 语法 + Model + Serializer 对 CMDB 做增删改查，团队大量复用 |

> 面试叙事（技术能力点）：*「为跨系统的数据源实现了 Django ORM 语义的 QuerySet 抽象，让团队能用熟悉的 ORM 语法操作外部 CMDB。」*
