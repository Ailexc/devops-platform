# 本地开发环境规范

> 版本：v1.0（2026-08-07）
> 适用范围：本项目所有开发者

---

## 一、背景与原则

本项目使用 **OrbStack** 作为 Docker Desktop 替代方案，所有服务通过 OrbStack 的自动域名功能进行访问，**禁止硬编码 localhost / 127.0.0.1**。

### 核心原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | **域名优先于端口** | 通过 `{service}.{project}.orb.local` 访问，不依赖固定端口 |
| 2 | **环境变量驱动** | 所有地址通过环境变量配置，不硬编码在代码中 |
| 3 | **项目隔离** | 每个项目使用独立的 Docker Compose project name，端口映射互不冲突 |
| 4 | **Ollama 例外** | Ollama 运行在宿主机，容器内访问需用 `host.docker.internal` |

---

## 二、OrbStack 域名规范

OrbStack 为 Docker Compose 服务自动生成域名，格式为：

```
{service-name}.{project-name}.orb.local
```

### 本项目域名映射

| 服务 | OrbStack 域名 | 用途 |
|------|--------------|------|
| `api` | `api.workflow.orb.local` | Django API 服务 |
| `frontend` | `frontend.workflow.orb.local` | 前端静态资源（Nginx） |
| `postgres` | 不需要外部访问 | 数据库（仅容器间通信） |
| `redis` | 不需要外部访问 | 缓存（仅容器间通信） |
| `worker` | 不需要外部访问 | Celery Worker |
| `beat` | 不需要外部访问 | Celery Beat |

### 端口映射规范

为避免多项目端口冲突，**不暴露服务端口到宿主机**（除非必要）。

| 服务 | 宿主机端口 | 容器端口 | 说明 |
|------|-----------|---------|------|
| postgres | `5433`（或项目专属） | 5432 | 避免与默认 5432 冲突 |
| redis | `6380`（或项目专属） | 6379 | 避免与默认 6379 冲突 |
| api | **不暴露** | 8000 | 通过 `api.workflow.orb.local` 访问 |
| frontend | **不暴露** | 80 | 通过 `frontend.workflow.orb.local` 访问 |

## 四、端口冲突解决方案

### 问题描述

多个项目同时使用 Docker Compose 时，如果端口映射相同（如都映射 5432、6379、8000），会端口冲突导致服务启动失败。

### 解决方案

#### 方案 A：OrbStack 域名优先（推荐）

移除宿主机端口映射，完全依赖 OrbStack 域名：

```yaml
# docker-compose.yml
services:
  api:
    # 不需要 ports 映射
    labels:
      dev.orbstack.domains: api.workflow.orb.local
  
  frontend:
    # 不需要 ports 映射
    labels:
      dev.orbstack.domains: frontend.workflow.orb.local
```

#### 方案 B：项目专属端口（备选）

为每个项目分配独立的端口范围：

| 项目 | PostgreSQL | Redis | API | Frontend |
|------|-----------|-------|-----|----------|
| workflow | 5433 | 6380 | 8001 | 5174 |
| release_system | 5434 | 6381 | 8002 | 5175 |
| cloud_manager | 5435 | 6382 | 8003 | 5176 |

## 五、Ollama 访问规范

Ollama 运行在宿主机，容器内访问方式：

| 场景 | 地址 | 说明 |
|------|------|------|
| Docker for Mac | `http://host.docker.internal:11434` | OrbStack / Docker Desktop 通用 |
| Linux Docker | `http://172.17.0.1:11434` | Docker bridge 网关 |
| 宿主机直接访问 | `http://localhost:11434` | 仅宿主机本地使用 |

### 配置方式

通过环境变量覆盖默认值：

```bash
# .env
AI_OLLAMA_API_BASE=http://host.docker.internal:11434/v1
```

```yaml
# docker-compose.yml
environment:
  - AI_OLLAMA_API_BASE=${AI_OLLAMA_API_BASE:-http://host.docker.internal:11434/v1}
```

## 六、开发启动流程

### 首次启动

```bash
# 1. 克隆项目
git clone <repo-url>
cd workflow

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env，填入 AI API Key 等

# 3. 启动服务
docker compose up -d

# 4. 初始化数据库
docker compose exec api python manage.py migrate
docker compose exec api python manage.py seed_data

# 5. 前端开发（可选，如需热更新）
cd frontend
npm install
npm run dev
```

### 访问地址

| 服务 | 地址 | 说明 |
|------|------|------|
| 前端（生产模式） | https://frontend.workflow.orb.local | Nginx + 静态资源 |
| 前端（开发模式） | http://localhost:5173 | Vite dev server（仅本地） |
| API | https://api.workflow.orb.local | Django REST API |
| Django Admin | https://frontend.workflow.orb.local/django-admin/ | 管理后台 |

### 前端开发模式代理配置

```javascript
// frontend/vite.config.js
server: {
  host: '0.0.0.0',
  port: 5173,
  proxy: {
    '/api': {
      target: 'http://api.workflow.orb.local',  // 使用 OrbStack 域名
      changeOrigin: true
    }
  }
}
```

## 七、多项目共存规范

### 项目命名规范

每个项目的 Docker Compose project name 应唯一：

```yaml
# docker-compose.yml
services:
  # ...
```

```bash
# .env
COMPOSE_PROJECT_NAME=workflow  # 项目名作为 OrbStack 域名前缀
```

### 端口分配表

建议维护一份端口分配表，避免冲突：

| 端口范围 | 用途 | 项目 |
|---------|------|------|
| 5432-5439 | PostgreSQL | 各项目 |
| 6379-6389 | Redis | 各项目 |
| 8000-8099 | API 服务 | 各项目 |
| 5173-5199 | 前端 dev server | 各项目 |

### 检查清单

开发新项目前，确认：

- [ ] `COMPOSE_PROJECT_NAME` 已设置且唯一
- [ ] 端口映射不与已有项目冲突
- [ ] OrbStack 域名不与已有项目冲突
- [ ] 代码中无硬编码的 localhost 引用
- [ ] 环境变量有合理的默认值
