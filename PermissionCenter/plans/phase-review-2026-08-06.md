## 一、项目目标回顾

### 1.1 项目定位

权限中心（IAM）demo，用于**面试展示 + 回忆知识点**。叙事主线是"重构后的现代化方案"，对比旧系统痛点（CMDB 强耦合、数据膨胀、权限配置繁琐、未调研业界方案）。

### 1.2 核心目标

| 目标 | 说明 |
|------|------|
| **API 权限管控** | OpenAPI → 权限模板 → 角色/组/用户授权 |
| **数据权限管控** | CMDB 数据模型 + 实例级勾选授权（check / filter） |
| **网关统一鉴权** | Traefik PEP → iam-server PDP |
| **现代实践体现** | PEP/PDP/PAP/PIP、控制面/数据面分离、策略即数据、策略分发与本地决策 |
| **去中心化授权** | 基于所有权的授权管理，授权全审批，组即角色 |
| **能力包全生命周期** | 声明 → 配置 → 上架 → 申请 → 审批 → 开通 → 回收 |

### 1.3 技术栈

| 层 | 技术 |
|----|------|
| 后端 | Go + Gin |
| 授权引擎 | Casbin（动作级）+ OpenFGA（实例级） |
| 数据库 | PostgreSQL + GORM |
| 缓存 | Redis |
| 网关 | Traefik（v3，forwardAuth） |
| 前端 | Vue3 + Vite + TypeScript |
| 部署 | Docker Compose（OrbStack） |

## 六、整体方向评估

### 6.1 方向是否偏移？

**结论：方向正确，未偏移。**

| 维度 | 评估 |
|------|------|
| **架构设计** | PEP/PDP/PAP/PIP 分离、Casbin + OpenFGA 双引擎、策略即数据 —— 均按计划实现 |
| **技术选型** | Go + Gin + GORM + PostgreSQL + Redis + Traefik + Vue3 —— 未偏离 |
| **叙事主线** | "重构后的现代化方案" —— 通过对比旧系统痛点、展示新架构优势，叙事清晰 |
| **面试价值** | 覆盖 RBAC/ABAC/ReBAC、PEP/PDP、策略分发、审计可观测 —— 知识点密度高 |
| **去中心化方向** | 组即角色、授权即审批、双向账本 —— 核心理念已落地 |

### 6.2 亮点（超出预期）

1. **全链路 e2e 验证**：demo.sh 11 步全过，从登录到网关鉴权到策略分发
2. **容器化部署**：OrbStack + Docker Compose 9 容器一键部署
3. **Seed 数据丰富**：12 用户 + 5 应用 + 组织树 + 多种策略场景
4. **系统观测**：Trace/Resolver/PIP/Agent 四页面，黑盒显性化
5. **UI 现代化**：方案 A 云原生企业蓝主题 + v12 demo 交互参考

### 6.3 风险与不足

1. **能力包生命周期未闭环**：预设级上架/下架、双主体、表达式构建器是核心叙事缺口
2. **前端样式一致性**：部分页面仍需统一（已优化能力编辑器，其他页面待跟进）
3. **测试覆盖**：无单元测试/集成测试，依赖手动验证
4. **文档滞后**：部分设计文档与实现有差距（如 refactor-plan 阶段 0 的 TTL）
