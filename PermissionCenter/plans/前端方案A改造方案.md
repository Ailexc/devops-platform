## 2. 目标与设计原则

1. **一个设计系统**：以方案 A token 为唯一基准，全站套用，删除各 view 重复样式；
2. **角色与任务驱动的信息架构**：按「自助服务 / 管理治理 / 审计合规 / 系统观测」分组，而非能力平铺；
3. **对齐 v12 demo**：应用详情补齐接口树/数据模型；编辑器/授权管理/市场向导视觉与 demo 一致；
4. **渐进但彻底**：先落设计系统与布局壳，再逐页套壳，最后全站校验（OrbStack 部署）。

## 4. 信息架构重构（左侧导航）

### 4.1 设计思路

参考：
- **Okta Admin**：按 Directory / Applications / Security / Reports / Settings 分组，角色导向；
- **Cloudflare Dashboard**：分组图标 + 激活态 + 面包屑；
- **Grafana**：按导航分区（Dashboards / Explore / Alerts / Administration）。

权限中心应体现的核心能力维度：**我能用（自助）→ 谁在用/谁能用（治理）→ 发生了什么（审计）→ 系统是否健康（观测）→ 平台配置（管理）**。

### 4.2 新导航分组（提案）

```
◇ 工作台

▓ 权限市场
  能力市场（已发布能力 → 权限申请）
  应用市场（已注册应用 → 接入申请：网络打通 + Token 凭证，前置动作）

▓ 审批中心（独立，按工单类型分类）
  权限申请 · 接入申请 · 上架 / 下架 · 授权回收（内部 mock + 真实场景说明卡片）

▓ 应用管理（核心，应用视角）
  应用列表 → 详情：基础信息 / 接口树 / 数据模型 / 网络信息 / 鉴权方式 / 接入与凭证

▓ 能力管理（核心，能力视角，独立菜单）
  能力列表（角色感知：管理员全部 / owner 仅自己应用；可按应用筛选）→ 查看 / 编辑 / 授权管理

▓ 审计与合规
  审计日志
  决策日志
  授权主体（只读账本）

▓ 系统观测（运维 / 演示 / 实验，插件式工具箱）
  鉴权链路追踪
  PEP 解析工作台
  身份解析（PIP）
  Agent · 分发 · 同步
  决策日志流 · 策略命中解释 · Check 沙盒 · 一键演示剧场（P0）
  健康面板 · 同步监控 · OpenFGA 关系浏览器 · Bundle 查看器 · 故障注入 · 工单透传测试台（P1）

▓ 管理设置（admin，非核心能力）
  组织与组             ← 降级：组织架构 / 组权限（基础设施，删不得但非日常）
  策略管理（低层兜底）   ← 降级：一般由审批流自动生成，仅兜底/排查使用
  用户管理
  程序身份（客户端）
  系统配置
```

> 用户已确认方向：① 应用管理 / 能力管理 **拆分为两个独立菜单**（应用详情不再塞能力相关，缓解拥挤）；② 权限市场分 **能力市场 / 应用市场** 两类（分别对应权限申请、接入申请=网络打通+Token）；③ 策略/组织/授权主体降级；④ 审批中心独立 + mock 工单 + 真实场景说明卡片（暂不真实接入透传）。

### 4.3 交互细节

- 分组标题小号大写灰色，条目带 SVG 图标 + active 蓝底（`--brand-soft`）；
- **面包屑**：顶部栏左侧（如 `应用管理 / cmdb / 主机管理 / 授权管理`），由路由 meta 生成；
- **顶部栏**：左侧面包屑 + **全局搜索**（按应用/能力/权限点，Cloudflare/Okta 式）；右侧「+ 申请权限」快捷按钮 / 主题切换 / 用户头像+名称；
- **角色感知**（P1）：普通用户隐藏「系统观测/管理设置」分组，owner/admin 可见（demo 阶段可用菜单配置项控制）；
- 市场入口保留显眼位置（`+ 申请权限` 顶栏按钮 + 侧边栏「能力市场」）。

### 4.4 审批中心设计（独立，按工单类型分类 + 外部工单透传）

- **统一工单视图**：聚合四类 —— 权限申请（AccessRequest 1/2/3）、接入申请（RequestOnboard）、上架/下架（CapabilityPublishTask）、授权回收（RevokeRequest）；
- **后端**：`GET /api/v1/tickets`（聚合：AccessRequest 1/2/3 + CapabilityPublishTask + RevokeRequest；类型筛选 + 我发起的/待我审批 + 状态）；**暂不真实接入透传**（D9 确认：内部 mock，预留 webhook 接口）；
- **前端**：审批中心按类型 tabs，每类展示 工单号 / 类型 / 发起人 / 状态 / 审批链 / 操作；顶部「待我审批」汇总数 + **真实场景说明卡片**（"生产环境：发起到公司工单平台（OA/ITSM），本系统透传查询外部状态，避免用户两头跑；当前为内部模拟"）。

### 4.5 系统观测扩容（插件式工具箱）

| 优先级 | 工具 | 说明 |
|--------|------|------|
| P0 | **Check 沙盒** | 输入 用户/应用/动作/实例 → 实时鉴权结果 + 命中策略解释（演示/排查两用） |
| P0 | **决策日志流** | 实时滚动展示决策日志（轮询/EventSource） |
| P0 | **策略命中解释** | 某次 check 为什么 allow/deny（决策日志钻取） |
| P0 | **一键演示剧场** | 把 demo.sh 场景做成可点击跑通：越权拦截 / 宕机降级 / 策略生效 / 接入签发 |
| P0 | **健康面板** | postgres/redis/openfga/traefik/cmdb 等组件状态灯 |
| P0 | **同步监控** | CMDB / Identity / OpenAPI 同步状态与重试 |
| P1 | OpenFGA 关系浏览器 / Bundle 查看器 / 故障注入（模拟降级观察）/ 工单透传测试台 | 后续按需追加 |

> 设计原则：观测 = 只读 + 实验，不污染生产数据；工具以「插件注册表」接入，想到什么加什么。

### 5.4 权限市场（能力市场 / 应用市场 分治）

- **能力市场**：面向「已发布能力」的权限申请；支持按应用浏览；能力卡增强（风险等级/申请量/鉴权方式徽标）、多维度筛选（应用/模型/标签/风险/鉴权方式）；
- **应用市场**：面向「已注册应用」的接入申请（网络打通 + Token 凭证，前置动作一次完成）；应用卡带健康/同步状态徽标；应用详情 = 网络信息 + 鉴权方式 + 「发起接入」；顶部紧凑「我的接入」状态条（已接入应用/凭证状态）；
- **申请向导主体步内联接入状态**：选下游应用时显示——已接入 ✓（凭证复用提示）/ 未接入 → 引导前往应用市场完成接入；
- 应用管理 / 应用市场语义区分：应用管理 = 我拥有的应用（owner 视角）；应用市场 = 全部应用（消费者视角，申请接入）。
- **接入与凭证职责划分**：应用管理详情 = 提供方视角（谁接入了我）；应用市场详情 = 消费方视角（我的凭证 / 发起接入），避免两块重复。

### 5.1 应用详情「接口树 / 数据模型」数据源说明

- 接口树：后端 `GET /apps/:id/actions`（已有）→ 前端按 resource 分组渲染；
- 数据模型：后端能力 `model_fields` + `GET /resource-models`（已有）→ 渲染字段表；
- 请求/响应示例：后端 action 暂无 req/resp 字段 —— **决策 D5**（mock 示例 or 后端补字段）。

## 7. 决策点（已定案，2026-08-05）

| # | 决策点 | 结论 |
|---|--------|------|
| D1 | 暗色模式 | **支持亮/暗切换**（双主题） |
