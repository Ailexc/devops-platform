📥

事件接收阶段

API Gateway 接收事件 → 校验签名/Schema → 生成 trace_id → 投递到 RabbitMQ → 立即返回 202 Accepted。所有校验失败的事件记录到 rejected 表用于审计。

🔀

事件路由阶段

Celery Worker 消费消息 → 根据 event_type 匹配 EventHandler 注册表 → 按优先级入处理队列。支持通配符匹配 (e.g. aws.ec2.*)。

⚡

事件处理阶段

EventHandler 执行业务逻辑，全部使用 async/await。阻塞操作 offload 到 asyncio.to_thread()。处理结果写入 Event Store，失败自动重试。

🔁

重试 & 死信阶段

指数退避重试 (1s → 4s → 16s → 64s → 256s)，最大 5 次。重试耗尽后自动进入死信队列，触发告警。支持手动回放死信事件。

⚙️ Worker 进程模型

🚀

Celery Worker (asyncio 模式)

所有事件 Handler 统一使用 async/await 编写。Celery 5.x 原生支持 async task，底层使用 Python asyncio 事件循环，单个 Worker 可处理数千并发连接。

# 启动命令
celery -A event_manager worker \
  -P threads \
  --concurrency=1000 \
  -Q events,events:high,events:low
🛡️

阻塞操作透明 Offload

遇到没有 async 支持的 SDK 调用、文件 IO、远程 API 请求，使用 asyncio.to_thread() 透明转移到线程池，不阻塞事件循环。

# 统一编程模型，无需手动区分快/慢
async def handle(event):
    # async 操作
    result = await query_cmdb(event.id)
    # 阻塞操作透明 offload
    ext = await asyncio.to_thread(
        slow_sdk_call, event.resource_id
    )
    return {**result, **ext}

📐 关键设计决策 ADR

架构设计中的关键决策、技术选型理由及与原始方案的对比。

🎯 核心目标

从你原来的 django-q 单机调度 + 手动并发模型升级为 分布式、可观测、高可用 的事件处理系统，同时保持代码的 统一编程模型 和 可测试性。

  • 架构归一 — 统一使用 Django Ninja，不再混用 FastAPI 和 Django 两套 Web 框架
  • 前后端分离 — 纯前端 UI 实现所有运维操作（列表、详情、重试、回放），不依赖 Django Admin
  • 统一异步 — API 层 + Worker 层全部 async，阻塞操作 offload 到线程池
决策项 原始方案 新方案 理由
任务队列 django-q (已停维) Celery 5.x + RabbitMQ Celery 是 Python 生态最成熟的任务队列，支持分布式 Worker、多种 Broker、重试、监控、异步任务原生支持
并发模型 进程 + 协程 + 线程 混用 统一 asyncio + ofload to_thread 开发者只需掌握 async/await 一种原语，心智模型统一，调试和异常处理更简单
事件存储 仅记录最终结果 Append-only Event Store 支持时间点回放、审计溯源、调试排错；Event Sourcing 模式天然支持 CQRS
API 响应 200 OK (处理完才返回) 202 Accepted (立即返回) 事件处理应该是异步的，不需要调用方等待处理完成，202 是标准做法
重试机制 仅告警，无自动重试 指数退避 (1s→256s) + 最大次数 临时故障（网络抖动、限流）是常态，自动重试大幅减少人工干预
死信处理 无 DLQ + 告警 + 手动回放 重试耗尽的事件不应丢弃，DLQ 提供兜底，支持人工介入
幂等性 未提及 事件 ID 去重 + 分布式锁 消息队列的"至少一次投递"特性要求幂等性，避免重复处理导致的数据不一致
可观测性 基础日志 Metrics + Tracing + Alerting 生产系统必须具备：Prometheus 指标、分布式追踪、结构化日志、告警规则
部署方式 单体 Django 进程 Web / Worker / Beat 分离部署 独立扩缩容、故障隔离、资源按需分配
Handler 注册 硬编码路由 声明式 Pattern 匹配注册表 新增事件类型只需注册新 Handler，无需修改路由逻辑，支持通配符匹配
